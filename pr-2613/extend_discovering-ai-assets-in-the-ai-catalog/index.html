Chapter 1. AI Catalog overview

The AI Catalog provides a marketplace-style interface to browse, search, filter, and discover AI assets registered in the Software Catalog, helping you find agents, skills, MCP servers, AI models, and model servers for your organization.

The AI Catalog is a dynamic front-end plugin that integrates with Developer Hub to give developers a dedicated discovery interface for AI capabilities. Instead of searching across multiple registries, repositories, and documentation sources, developers use a single catalog with category grouping, contextual filtering, and download actions.

The AI Catalog provides the following capabilities:

  • Browse AI assets — View all available AI agents, skills, MCP servers, AI models, and model servers in a card-based grid layout
  • Search and filter — Find assets by name, description, or tag, and narrow results by category, source connector, or lifecycle
  • View asset details — Access complete information about each asset including name, description, versions, source registry, and usage documentation
  • Copy deployment commands — For OCI-based assets, copy docker or podman pull commands directly from the detail page
  • Understand dependencies — View version lists and identify the recommended version for each asset

The AI Catalog is a discovery and metadata browsing interface. Version 1 explicitly excludes the following capabilities:

  • Install, deploy, or run actions for AI assets
  • Ratings, reviews, or usage analytics
  • Notifications or alerts for new assets
  • In-UI editing or curation of asset metadata

After you find an asset in the AI Catalog, follow the usage documentation or external links to install, configure, and use the asset in your environment.

The AI Catalog integrates with the following Developer Hub components:

  • Software Catalog API — Retrieves AI Asset entities with required annotations
  • Search infrastructure — Enables federated search across AI assets and other catalog entities
  • TechDocs — Renders usage documentation when TechDocs references are present on entities
  • Permission Framework (optional) — Enforces RBAC visibility policies when configured

The AI Catalog supports the following asset categories:

CategoryDescription

AI Agents

Autonomous AI systems that perform tasks by using tools and skills

AI Skills

Reusable capabilities that agents call to accomplish specific tasks

MCP Servers

Model Context Protocol servers that expose tools and resources to AI clients

AI Models

Machine learning models for inference and prediction

Model Servers

Deployment platforms that serve AI models at runtime

Chapter 2. Enable and configure the AI Catalog plugin

To allow developers to browse and discover AI assets, enable the AI Catalog dynamic plugin and optionally configure filter visibility.

2.1. Enable the AI Catalog plugin

To allow developers to discover AI assets, enable the AI Catalog dynamic plugin in your Developer Hub instance.

Prerequisites

  • You have administrator access to your Developer Hub instance.
  • AI Asset entities are ingested into the Software Catalog.
  • The entities include the required annotations: rhdh.io/ai-asset-category, rhdh.io/ai-asset-version, and rhdh.io/ai-asset-source.

Procedure

  1. Edit your dynamic-plugins-rhdh ConfigMap to include the AI Catalog plugin: 

    kind: ConfigMap
apiVersion: v1
metadata:
  name: dynamic-plugins-rhdh
data:
  dynamic-plugins.yaml: |
    includes:
      - dynamic-plugins.default.yaml
    plugins:
      - package: '@redhat/backstage-plugin-ai-catalog'
        disabled: false

  2. Optional: Configure filter visibility in your app-config.yaml or app-config-rhdh ConfigMap: 

    app:
  extensions:
    - entity-ref: 'plugin:ai-catalog'
      config:
        filters:
          owner:
            disabled: true  # Hide the owner filter

  3. Apply the updated ConfigMap: 

    $ oc apply -f <configmap-file>

    where <configmap-file> is the path to your updated ConfigMap YAML file.

  4. Restart the Developer Hub pods to load the plugin: 

    $ oc rollout restart deployment/backstage

Verification

  1. Navigate to your Developer Hub instance in a web browser.
  2. Confirm that an AI Catalog menu item is displayed in the navigation sidebar.
  3. Click AI Catalog and verify that AI assets are displayed in the card grid.

2.2. Configure AI Catalog filters

To control which filters appear in the AI Catalog sidebar, configure filter visibility in your application configuration.

Prerequisites

  • You have administrator access to your Developer Hub instance.
  • The AI Catalog plugin is enabled.

Procedure

  1. Edit your app-config-rhdh ConfigMap to configure filter visibility: 

    app:
  extensions:
    - entity-ref: 'plugin:ai-catalog'
      config:
        filters:
          owner:
            disabled: true
          lifecycle:
            disabled: false

    where:

    owner
    Disables the owner filter, hiding it from the filter sidebar.
    lifecycle
    Enables the lifecycle filter, showing it in the filter sidebar.

  2. Apply the updated ConfigMap: 

    $ oc apply -f <configmap-file>

  3. Restart the Developer Hub pods: 

    $ oc rollout restart deployment/backstage

Verification

  1. Navigate to the AI Catalog in your browser.
  2. Confirm that the configured filters appear or do not appear in the sidebar based on your settings.

The following table lists the available filters:

FilterDescription

category

Filters by AI asset category (AI Agents, AI Skills, MCP Servers, AI Models, Model Servers)

source

Filters by source connector (MCP Registry, RHOAI, JFrog, Solo Agentregistry)

tags

Filters by tags and labels applied to assets

owner

Filters by asset owner (optional, can be disabled)

lifecycle

Filters by asset lifecycle status (optional, can be disabled)

Chapter 3. Browse AI assets in the catalog

To find AI capabilities for your application, browse the AI Catalog by using search, filters, and category grouping.

Prerequisites

  • The AI Catalog plugin is enabled in your Developer Hub instance.
  • AI assets are registered in the Software Catalog.

Procedure

  1. Navigate to your Developer Hub instance and click AI Catalog in the sidebar.

    The AI Catalog landing page displays all AI assets you are authorized to view, grouped by category.

  2. Optional: Search for assets by name, description, or tag:

    1. Type keywords into the search box at the top of the page.
    2. Results update as you type, showing only assets matching your search terms.

  3. Optional: Filter assets by category, source, or tags:

    1. Open the filter sidebar on the left side of the page.
    2. Select one or more categories: AI Agents, AI Skills, MCP Servers, AI Models, or Model Servers.
    3. Select one or more source connectors to filter by origin: MCP Registry, RHOAI, JFrog, or Solo Agentregistry.
    4. Select tags or labels to narrow results further.
    5. Click Clear filters to reset all filter selections.

  4. Optional: Combine search and filters to narrow large result sets:

    1. Type keywords in the search box.
    2. Apply filters in the sidebar.
    3. The catalog displays only assets matching both your search terms and selected filters.

  5. Review asset cards in the grid:

    Each card displays the following information:

  6. Asset name
  7. Short description
  8. Category icon or label
  9. Source connector
  10. Current or recommended version
  11. Owner (if visible)
  12. Click an asset card to view its detail page.

Verification

  1. Assets matching your search terms and filter selections appear in the catalog grid.
  2. The catalog shows a "no results" message if no assets match your current filters.

Chapter 4. View AI asset details

To understand what an AI asset does and how to use it, view its detail page showing complete metadata, versions, and usage documentation.

Prerequisites

  • The AI Catalog plugin is enabled in your Developer Hub instance.
  • You have browsed the AI Catalog and located an asset.

Procedure

  1. In the AI Catalog, click an asset card.

    The asset detail page opens, displaying complete information about the asset.

  2. Review the AI Asset Summary card:

    • Asset name
    • Full description
    • Category and type
    • Source registry and ingestion connector
    • Owner
    • Lifecycle status

  3. Review the Version List card:

    • List of all available versions
    • Current or recommended version (highlighted)
    • Version history

  4. Review the How to use this panel or Usage tab:

    • If the asset has TechDocs documentation, the panel renders setup instructions, configuration snippets, and usage examples inline.

    • If the asset does not have TechDocs, the panel displays links to:

      • Source registry entry
      • Source repository
      • Download or distribution location

  5. Optional: For OCI-based assets (skills published as container images), copy deployment commands:

    1. Locate the Download or Adopt card on the detail page.
    2. Click Copy next to the docker pull or podman pull command.
    3. Paste the command into your terminal to pull the asset image.

Verification

  1. The detail page displays the asset name, description, category, versions, and usage documentation or external links.
  2. For OCI-based assets, the Download or Adopt card shows a complete pull command with registry URL, namespace, image name, and digest.

Chapter 5. Understand AI Catalog architecture and dependencies

The AI Catalog integrates with existing Developer Hub infrastructure and requires specific entity metadata to function, making it compatible with air-gapped deployments.

5.1. AI Catalog architecture and dependencies

The AI Catalog integrates with existing Developer Hub components to provide AI asset discovery without introducing new backend services or network requirements.

The AI Catalog is a front-end dynamic plugin that reuses existing Developer Hub infrastructure:

  • Software Catalog API — Retrieves AI Asset entities from the catalog backend
  • Search infrastructure — Enables federated search, returning AI assets alongside other catalog entities in global search results
  • TechDocs rendering — Displays usage documentation when entities include TechDocs references
  • Permission Framework (optional) — Enforces RBAC visibility policies defined for AI assets

The plugin does not introduce a new backend service. All data flows through the existing Developer Hub backend API.

The AI Catalog requires the following components to function:

ComponentPurposeStatus

AI Asset entities

Entities registered in the Software Catalog with required annotations (rhdh.io/ai-asset-category, rhdh.io/ai-asset-version, rhdh.io/ai-asset-source)

Required

Ingestion connectors

Populate the Software Catalog with AI assets from external registries (MCP Registry, RHOAI, JFrog, Solo Agentregistry)

Required

RBAC policies (RHDHPLAN-1508)

Define visibility and access control for AI assets (ai-catalog.asset.read, ai-catalog.asset.read.usage-docs)

Optional (available in RHDH 2.2+)

TechDocs content

Provides rich inline usage documentation for assets

Optional

The AI Catalog is fully compatible with disconnected and air-gapped OpenShift Container Platform environments:

  • All assets, icons, and TechDocs content are served from in-cluster sources
  • No required runtime calls to external or internet-hosted endpoints
  • External links (to source registries, repositories, or download locations) open in new tabs and degrade gracefully if unreachable
  • Custom CA bundles can be configured for internal registries if needed

The AI Catalog does not require additional network egress beyond the existing Developer Hub backend.

The AI Catalog is designed to handle large catalogs with responsive performance:

  • Initial page load completes in under 2 seconds for catalogs with 500 assets
  • Filter application completes in under 2 seconds
  • Pagination or virtualization prevents UI lag with large result sets
  • Catalog API performance impact is less than 10% compared to baseline (non-AI-Catalog entity queries)

5.2. AI Asset entity model

AI assets are represented as Software Catalog entities with specific annotations that define their category, version, and source registry.

All AI Asset entities must include the following annotations for the AI Catalog to display them correctly:

AnnotationDescription

rhdh.io/ai-asset-category

The category of the AI asset. Valid values: agent, skill, mcp-server, ai-model, model-server

rhdh.io/ai-asset-version

The version of the asset, normalized to a semantic version format (for example, 1.0.0)

rhdh.io/ai-asset-source

The ingestion connector and registry that provided the entity (for example, mcp-registry, rhoai, jfrog, agentregistry)

Skills and other assets published as OCI container images include an additional annotation for registry details:

AnnotationDescription

rhdh.io/oci-registry

The OCI registry reference, including registry URL, namespace, image name, and digest

AI assets use the AiResource entity kind with spec.type values corresponding to their category:

Categoryspec.typeDescription

AI Agent

ai-agent

Autonomous systems that perform tasks by using tools and skills

AI Skill

ai-skill

Reusable capabilities invoked by agents to accomplish tasks

MCP Server

mcp-server

Model Context Protocol servers exposing tools and resources

AI Model

ai-model

Machine learning models for inference and prediction

Model Server

model-server

Deployment platforms serving AI models at runtime

The following example shows an AI skill entity with required annotations: 

apiVersion: backstage.io/v1alpha1
kind: AiResource
metadata:
  name: python-testing-skill
  namespace: default
  annotations:
    rhdh.io/ai-asset-category: skill
    rhdh.io/ai-asset-version: 1.2.0
    rhdh.io/ai-asset-source: mcp-registry
    rhdh.io/oci-registry: quay.io/rhdh/python-testing-skill@sha256:abc123
spec:
  type: ai-skill
  owner: team-ai
  lifecycle: production

To display rich usage documentation in the AI Catalog detail page, add a TechDocs reference to the entity: 

metadata:
  annotations:
    backstage.io/techdocs-ref: dir:.

When a TechDocs reference is present, the AI Catalog renders the documentation inline in the "How to use this" panel. Without a TechDocs reference, the catalog displays links to the source registry, repository, or download location.
