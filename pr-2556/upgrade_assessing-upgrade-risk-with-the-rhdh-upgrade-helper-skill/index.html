Preface

The RHDH Upgrade Helper is a community Claude Code skill that helps platform engineers self-assess upgrade risk before upgrading Red Hat Developer Hub between released versions. Supply your configuration files to receive a prioritised report of predicted issues to address before upgrading.

Chapter 1. About the RHDH Upgrade Helper skill

The RHDH Upgrade Helper is a community Claude Code skill in rhdh-users-skill-pack. It helps platform engineers identify upgrade risks before upgrading a RHDH instance between released versions, including minor (for example, 1.8 to 1.10) and major upgrades.

Note

The RHDH Upgrade Helper skill is a community tool distributed under an open-source licence. It does not require a Red Hat subscription.

1.1. What the skill analyses

When you run the skill with your configuration files and target version, it cross-references your environment against upstream Backstage and Red Hat Developer Hub documentation and known public bug data. The skill identifies the following categories of risk:

Breaking changes in upstream Backstage APIs
API changes between the current and target Backstage versions that may affect your plugins or backend configuration.
Configuration drift
Settings in your app-config.yaml or dynamic plugins configuration that are deprecated, removed, or behave differently in the target version.
Plugin compatibility issues
Plugins in your current configuration that are incompatible with, or require updates for, the target RHDH version.
Known upgrade failure patterns
Historical upgrade issues surfaced from public RHDH bug data relevant to your version range.

1.2. What the skill produces

The skill writes a structured, prioritised report to your terminal. The report lists each predicted issue by severity, explains the impact, and describes the action required before upgrading.

When skipping multiple minor versions — for example, upgrading from 1.5 to 1.9 — the skill accumulates predicted issues across all skipped releases into a single report.

1.3. Red Hat Developer Hub Local recommendation

If you are not already using Red Hat Developer Hub Local (RHDH Local), the skill recommends it as a safe, cluster-free environment for validating your configuration against the target version before upgrading your production instance. RHDH Local uses rhdh-local with Podman Compose and does not require a Kubernetes cluster.

1.4. Security and secrets handling

The skill does not process secret values. Before analysing any input files, the skill:

  • Warns you not to include API keys, passwords, tokens, or credentials in configuration files or environment variable exports.
  • Applies defensive checks to flag content that appears to contain secrets.

Do not provide configuration files that contain secret values to the skill.

Chapter 2. Run the RHDH Upgrade Helper skill

Run the RHDH Upgrade Helper skill to produce a prioritised report of predicted upgrade issues for your Red Hat Developer Hub instance.

Prerequisites

  • You have Claude Code installed and authenticated.
  • You have cloned or installed the rhdh-users-skill-pack repository, or you have added the skill pack to your Claude Code configuration.

  • You have access to your current RHDH configuration files:

    • app-config.yaml — the Red Hat Developer Hub application runtime configuration file.
    • Your dynamic plugins configuration YAML — the file that controls plugin enablement, versions, and overrides.
  • Optional: You have a file containing your runtime environment variable values (for example, a .env file) that affect RHDH behaviour.
Important

Do not include API keys, passwords, tokens, or other credentials in any files you provide to the skill. The skill checks for secrets and warns you if it detects content that appears to contain sensitive values, but you must ensure secret values are removed or replaced with placeholders before proceeding.

Procedure

  1. Open a terminal and change to the directory that contains your RHDH configuration files.

  2. Run the skill by starting Claude Code with the rhdh-users-skill-pack active and invoking the upgrade helper skill: 

    $ claude --skill rhdh-upgrade-helper \
  --from <current_version> \
  --to <target_version> \
  --config app-config.yaml \
  --plugins dynamic-plugins.yaml

    Replace <current_version> with your installed RHDH version (for example, 1.8) and <target_version> with the version you are upgrading to (for example, 1.10).

  3. Optional: Provide your environment variable file to include runtime configuration in the analysis: 

    $ claude --skill rhdh-upgrade-helper \
  --from <current_version> \
  --to <target_version> \
  --config app-config.yaml \
  --plugins dynamic-plugins.yaml \
  --env .env

  4. Optional: If you have additional configuration files relevant to your deployment, provide them using repeated --config flags: 

    $ claude --skill rhdh-upgrade-helper \
  --from 1.5 \
  --to 1.9 \
  --config app-config.yaml \
  --config app-config.production.yaml \
  --plugins dynamic-plugins.yaml
  5. Review the predicted-issues report that the skill writes to your terminal. The report lists each issue in priority order. Address the issues listed before starting the upgrade.

Verification

  1. The skill produces a prioritised report in your terminal that lists predicted breaking changes, configuration drift, and plugin compatibility issues for your specified upgrade path.
  2. If the skill detects that you are not using Red Hat Developer Hub Local (RHDH Local), it recommends using it to validate your configuration against the target version in a cluster-free environment before upgrading production.

Additional resources

  • rhdh-users-skill-pack on GitHub
  • rhdh-local on GitHub

Chapter 3. Configuration inputs for the RHDH Upgrade Helper skill

The RHDH Upgrade Helper skill requires specific configuration files to analyze your Red Hat Developer Hub deployment. The following tables describe the required and optional inputs, and the available command-line flags.

3.1. Required inputs

InputFlagDescription

Application configuration

--config <path>

Path to your app-config.yaml file. This file contains the Red Hat Developer Hub application runtime configuration. You can specify this flag more than once to include additional configuration files, such as environment-specific overlays.

Dynamic plugins configuration

--plugins <path>

Path to your dynamic plugins configuration YAML file. This file controls which plugins are enabled, their versions, and any overrides applied to your deployment.

3.2. Optional inputs

InputFlagDescription

Environment variables

--env <path>

Path to a file containing runtime environment variable values (for example, a .env file). Include only variables that affect RHDH behaviour. Do not include secrets.

Additional configuration files

--config <path> (repeated)

Path to any additional configuration files relevant to your deployment, such as production overlays or custom backend configuration files.

3.3. Version flags

FlagDescription

--from <version>

The RHDH version currently installed in your environment. For example, 1.8.

--to <version>

The RHDH version you intend to upgrade to. For example, 1.10 or 2.1.

When you use --from and --to to specify a range that skips multiple minor versions, the skill produces a cumulative report covering all breaking changes, configuration changes, and plugin compatibility issues across every skipped release.

3.4. Secrets handling

The skill checks all provided input files for content that appears to contain secret values, such as API keys, tokens, or passwords, before processing them. If the skill flags a file, remove or replace the secret values with placeholders and re-run the skill.

Important

Do not provide configuration files or environment variable exports that contain live secret values. The skill warns against including secrets, but you are responsible for ensuring that sensitive data is not present in any files you provide.
