= Install an NFS custom plugin in {product}

[role="_abstract"]
To install a custom front-end plugin in {product} 2.1, create a plugin for the new front-end system (NFS) and package it as an OCI image. The generated plugin declares NFS extensions without Scalprum configuration or a callback manifest.

.Prerequisites
* You have Node.js 22, Yarn 4, Podman, and access to an OCI registry. The CLI packaging step also requires `bash`, `npm` 7 or later, and `tar` on your `PATH`.
* You have access to the dynamic plugin configuration for your {product-very-short} instance.

Replace _<your_namespace>_ in the following commands and configuration with your Quay.io namespace.

.Procedure
. Generate a front-end plugin matched to {product-very-short} 2.1:
+
[source,terminal,subs="+quotes"]
----
$ *npx @red-hat-developer-hub/cli@2.1.0 plugin new simple-example --type frontend --rhdh-version 2.1.0*
----
+
The generated project default-exports an NFS plugin from its root entry point and includes a `dev/` harness. You can add extension blueprints before packaging it.
. Change to the plugin directory:
+
[source,terminal,subs="+quotes"]
----
$ *cd simple-example*
----
. Install the plugin dependencies:
+
[source,terminal,subs="+quotes"]
----
$ *yarn install*
----
. Export the plugin:
+
[source,terminal,subs="+quotes"]
----
$ *npx @red-hat-developer-hub/cli@2.1.0 plugin export*
----
+
The front-end export writes standard module federation assets under `dist-dynamic/dist/`, including `remoteEntry.js`, and NFS feature metadata in the exported package. It does not create `dist-scalprum/`.
. Package the plugin as an OCI image:
+
[source,terminal,subs="+quotes"]
----
$ *npx @red-hat-developer-hub/cli@2.1.0 plugin package --tag quay.io/_<your_namespace>_/simple-example:v1*
----
. Log in to Quay.io:
+
[source,terminal,subs="+quotes"]
----
$ *podman login quay.io*
----
. Push the image:
+
[source,terminal,subs="+quotes"]
----
$ *podman push quay.io/_<your_namespace>_/simple-example:v1*
----
. Add the image to the dynamic plugin configuration:
+
[source,yaml,subs="+quotes"]
----
plugins:
  - package: oci://quay.io/_<your_namespace>_/simple-example:v1
    enabled: true
----
+
Plugin installation does not require a `pluginConfig.dynamicPlugins.frontend` block. The application discovers the installed plugin's extensions by default. Use `app.extensions` in your application configuration only to disable or customize a specific extension.

.Verification
After {product-very-short} restarts, open the page supplied by the generated plugin. If the page is missing, check the backend logs for a missing front-end manifest and the browser console for a skipped NFS feature export.
