= Install and configure an external TechDocs add-on using the Operator

[role="_abstract"]
You can use a dynamic plugin to import TechDocs add-ons into your TechDocs plugin. If you use the {product} Operator to install the dynamic plugin, you can add TechDocs add-ons to the plugin package in your ConfigMap.

Preinstalled add-ons, such as `ReportIssue`, are included in the default `backstage-plugin-techdocs-module-addons-contrib` package. In {product} {product-version}, the new front-end system registers these add-ons in code by using `AddonBlueprint` from `@backstage/plugin-techdocs-react/alpha`, and they are enabled by default. You no longer wire them through the `dynamicPlugins.frontend.<plugin>.techdocsAddons` section. To enable or disable a specific add-on, reference its extension ID in the `app.extensions` section of your application configuration.

.Procedure

. From the Developer perspective in the {ocp-short} web console, click *ConfigMaps* > *Create ConfigMap*.
. From the *Create ConfigMap* page, select the *YAML view* option in the *Configure via* field.
. In the newly created ConfigMap, enable the default `backstage-plugin-techdocs-module-addons-contrib` package. For example:
+
[source,yaml,subs="+quotes,+attributes"]
----
kind: ConfigMap
apiVersion: v1
metadata:
  name: dynamic-plugins-rhdh
data:
  dynamic-plugins.yaml: |
    includes:
      - dynamic-plugins.default.yaml
    plugins:
      - package: ./dynamic-plugins/dist/backstage-plugin-techdocs-module-addons-contrib
        disabled: false
----
+
The add-ons in this package are registered in code and enabled by default. No `techdocsAddons` wiring is required.
. To enable or disable a specific add-on, reference its extension ID in the `app.extensions` section of your application configuration. For example:
+
[source,yaml,subs="+quotes,+attributes"]
----
app:
  extensions:
    - addon:techdocs/_<external_techdocs_add-on>_: true
----
+
where:

_<external_techdocs_add-on>_:: Specifies the extension name of the external TechDocs add-on that you want to enable or disable, for example, `text-size` or `light-box`.
. Click *Create*.
. In the web console navigation menu, click *Topology*.
. Click the overflow menu for the {product} instance that you want to use and select *Edit {product-custom-resource-type}* to load the YAML view of the {product} instance.
. In your `{product-custom-resource-type}` CR, add the `dynamicPluginsConfigMapName: _<dynamic_plugins_configmap>_` key-value pair. For example:
+
[source,yaml,subs="+attributes,+quotes"]
----
apiVersion: rhdh.redhat.com/v1alpha5
kind: {product-custom-resource-type}
metadata:
  name: my-rhdh
spec:
  application:
# ...
    dynamicPluginsConfigMapName: _<dynamic_plugins_configmap>_
# ...
----
+
where:

_<dynamic_plugins_configmap>_:: Specifies the name of your dynamic plugins ConfigMap for your {product} instance, for example, `dynamic-plugins-rhdh`.
. Click *Save*.
. In the web console navigation menu, click *Topology* and wait for the {product} pod to start.
. Click the *Open URL* icon to start using the {product} platform with the new configuration changes.
