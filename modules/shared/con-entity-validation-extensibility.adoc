= Display validation feedback on catalog entities

[role="_abstract"]
The entity overview tab supports plugin-contributed validation messages that provide immediate feedback about entity health, configuration issues, and compliance status.
Multiple plugins can contribute validation messages simultaneously, each displayed with appropriate severity indicators.

== What is entity validation extensibility

Entity validation extensibility allows plugins to contribute validation messages to the entity overview tab.
These messages appear in a dedicated validation section on the overview page, providing users with immediate visibility into entity health and configuration problems.

Validation messages include:

* **Error**: Critical issues that prevent the entity from functioning correctly
* **Warning**: Issues that should be addressed but do not prevent basic functionality
* **Info**: Informational messages about entity configuration or best practices

== Why display validation feedback

Entity validation extensibility provides the following benefits:

* **Immediate visibility**: Users see configuration issues when viewing entity pages
* **Centralized feedback**: All validation messages from multiple plugins appear in one location
* **Clear severity**: Color-coded indicators help users prioritize issues
* **Actionable information**: Messages can include links to documentation or remediation procedures

== How entity validation works

Plugins contribute validation extensions through their `/alpha` export using extension blueprints.
The entity overview tab discovers these extensions automatically and evaluates them when rendering an entity page.

Each validation extension:

. Receives the entity data as input
. Evaluates the entity against plugin-specific rules or requirements
. Returns zero or more validation messages with severity levels
. Renders messages in the validation section with appropriate visual indicators

Multiple plugins can contribute validation messages for the same entity.
All messages appear together in the validation section, grouped by severity.

== Validation message severity levels

[cols="1,1,2", options="header"]
|===
|Severity
|Visual indicator
|Usage

|Error
|Red exclamation icon
|Critical issues that prevent the entity from working correctly. Example: Required annotation missing.

|Warning
|Yellow warning icon
|Issues that should be addressed but do not prevent basic functionality. Example: Deprecated API version.

|Info
|Blue information icon
|Informational messages about configuration or best practices. Example: Enhancement suggestions.
|===

== Relationship to backend entity processors

Frontend validation message extensions complement backend entity processors:

Backend processors:: Validate entities during ingestion and prevent invalid entities from entering the catalog.
Frontend validators:: Display validation feedback to users browsing existing entities and provide contextual information.

Both mechanisms work together to ensure entity quality and provide actionable feedback to users.

== Auto-discovery of validation extensions

When a plugin with validation extensions is installed in the `dynamic-plugins-root` directory, {product} automatically discovers and loads the extensions.
Validation messages appear automatically on entity pages without explicit configuration.
