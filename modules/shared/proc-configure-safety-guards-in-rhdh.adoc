= Enable query validation to block off-topic AI responses

[role="_abstract"]
Enable the question-validity shield to classify each prompt before {ia-name} answers it, so that off-topic or harmful prompts never reach your answering model.

In {product-very-short} {product-version}, {ia-name} validates prompts through a single question-validity shield that {lcs-name} ({lcs-short}) defines in the `lightspeed-stack.yaml` configuration file. This shield replaces the Llama Guard safety provider, registered shield resources, and `run.yaml` overrides used in earlier releases. Do not edit {ogx-name} ({ogx-short}) files or the generated `run.yaml` file to change validation behavior.

The shipped `lightspeed-stack.yaml` file includes the shield in a disabled state. You enable or disable the shield through environment variables in the Kubernetes Secret that {lcs-short} reads. When you enable the shield, {lcs-short} sends each prompt to the validation model, which classifies the prompt as allowed or rejected.

.Prerequisites

* You have an inference provider configured and enabled in the `inference.providers` section of your `lightspeed-stack.yaml` file.
* You can edit the Kubernetes Secret that supplies environment variables to the `lightspeed-core` container.

. To enable query validation, add the following keys to the Secret that {lcs-short} reads:
+
[source,yaml]
----
stringData:
  ENABLE_VALIDATION: question_validity
  VALIDATION_PROVIDER: <provider_type>
  VALIDATION_MODEL_NAME: <model_name>
----
+
where:
+
`ENABLE_VALIDATION`:: Specifies whether the shield is enabled. You must set the value to `question_validity`. A nonempty value such as `true` does not enable the shield in {product-very-short} {product-version}.
`VALIDATION_PROVIDER`:: Specifies the type of the inference provider that runs the classification, for example, `openai` or `vllm`. A provider of this type must be enabled in `inference.providers`.
`VALIDATION_MODEL_NAME`:: Specifies the model that classifies each prompt. If the provider defines `allowed_models`, include this model in that list.
+
For example, to run classification on an `openai` provider with the `gpt-4o-mini` model, set the following values:
+
[source,yaml]
----
stringData:
  ENABLE_VALIDATION: question_validity
  VALIDATION_PROVIDER: openai
  VALIDATION_MODEL_NAME: gpt-4o-mini
----

. To keep query validation disabled, leave `ENABLE_VALIDATION` unset, or set it to `__disabled__`:
+
[source,yaml]
----
stringData:
  ENABLE_VALIDATION: __disabled__
----
+
[IMPORTANT]
====
Running without query validation increases the risk of off-topic or harmful model output. Disable validation only in secure development environments.
====

. Apply the updated Secret, and then restart the {lcs-short} service so that the container reads the new environment variables.

.Verification
. Open *Intelligent Assistant* and submit a development question, for example, `How do I create a software template in {product-very-short}?`. Confirm that the assistant answers the question.
. Submit a clearly unrelated question, for example, `What is a good recipe for pizza?`. Confirm that the assistant rejects the question when validation is enabled.
