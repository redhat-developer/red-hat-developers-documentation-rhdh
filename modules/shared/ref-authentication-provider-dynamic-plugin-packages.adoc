= Authentication provider dynamic plugin packages

[role="_abstract"]
In {product}, authentication providers are dynamic plugins. To use an authentication
provider, install its dynamic plugin package and enable it in your `dynamic-plugins.yaml`
file, in addition to configuring `auth.providers.<id>` in your `{my-app-config-file}`
file.

The following table lists the supported authentication provider packages:

[cols="1,1,2",options="header"]
|===
|Authentication provider |Provider ID |Package

|Guest
|`guest`
|`@backstage/plugin-auth-backend-module-guest-provider`

|GitHub
|`github`
|`@backstage/plugin-auth-backend-module-github-provider`

|GitLab
|`gitlab`
|`@backstage/plugin-auth-backend-module-gitlab-provider`

|Microsoft / {azure-brand-name}
|`microsoft`
|`@backstage/plugin-auth-backend-module-microsoft-provider`

|Generic OIDC
|`oidc`
|`@backstage/plugin-auth-backend-module-oidc-provider`

|Keycloak
|`keycloak`
|`@backstage-community/plugin-auth-backend-module-keycloak-provider`

|PingFederate
|`pingfederate`
|`@backstage-community/plugin-auth-backend-module-pingfederate-provider`
|===

Each package is listed in the supported plugins catalog as disabled by default. Enable
only the authentication providers that you use.

To enable a provider, add its package to your `dynamic-plugins.yaml` file and set
`enabled` to `true`, as shown in the following example for the GitHub provider:

[source,yaml]
----
plugins:
  - package: oci://quay.io/rhdh/backstage-plugin-auth-backend-module-github-provider:{{inherit}}
    enabled: true
----

[IMPORTANT]
====
Configuring `auth.providers.<id>` without installing and enabling the matching dynamic
plugin does not register the provider. No authentication provider is installed by
default.
====
