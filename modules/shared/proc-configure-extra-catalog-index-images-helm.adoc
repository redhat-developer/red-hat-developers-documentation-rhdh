= Configure extra catalog index images with the Helm chart

[role="_abstract"]
Add extra catalog index images to your Helm chart deployment to make plugins from community, partner, and internal custom catalogs discoverable in the Extensions UI.

.Prerequisites

* You have deployed or are preparing to deploy {product} using the Helm chart.
* You have access to the catalog index image registries you want to configure.
* You understand the distinction between primary and extra catalog index images.

.Procedure

. Open your Helm chart `values.yaml` file for editing.

. Add the `global.catalogIndex.extraImages` parameter with entries for each extra catalog index image you want to configure:
+
[source,yaml]
----
global:
  catalogIndex:
    extraImages:
      - name: community
        registry: quay.io
        repository: community/rhdh-plugin-catalog
        tag: v1.10.0
      - registry: registry.example.com
        repository: internal/custom-plugins
        tag: latest
----
+
In this example:
+
. The first entry uses an explicit `name: community`, which creates the subdirectory `/extensions/extra/community/catalog-entities/`.
. The second entry omits the `name` field, so {product} auto-derives the subdirectory name from the image reference: `registry.example.com_internal_custom-plugins_latest`.

. For each extra catalog entry, provide the following fields:
+
`name` (optional):: The subdirectory name under `/extensions/extra/` where catalog entities are extracted. If omitted, {product} auto-derives the name from the image reference.
+
`registry` (required):: The container registry hostname (for example, `quay.io`, `registry.example.com`).
+
`repository` (required):: The repository path within the registry (for example, `community/rhdh-plugin-catalog`).
+
`tag` (required):: The image tag (for example, `v1.10.0`, `latest`).

. Deploy or upgrade the Helm chart:
+
[source,terminal]
----
$ helm upgrade my-rhdh redhat-developer/backstage \
    --install \
    --values values.yaml \
    --namespace {my-product-namespace}
----

.Verification

. Wait for the {product} deployment to complete and all pods to reach the `Running` state:
+
[source,terminal]
----
$ kubectl get pods -n {my-product-namespace}
----

. Verify that the extra catalog entities were extracted by inspecting the `install-dynamic-plugins` init container logs:
+
[source,terminal]
----
$ kubectl logs -n {my-product-namespace} \
    <pod_name> \
    -c install-dynamic-plugins
----
+
Replace `<pod_name>` with the name of your {product} pod.
Look for log messages indicating extraction of extra catalog index images.

. Verify the subdirectory structure by executing a shell in the {product} container:
+
[source,terminal]
----
$ kubectl exec -n {my-product-namespace} <pod_name> -- ls -l /extensions/extra/
----
+
You should see subdirectories corresponding to the `name` values or auto-derived names from your `extraImages` configuration.

. Verify that plugins from the extra catalogs appear in the Extensions UI:
+
--
.. Navigate to your {product} instance in a web browser.
.. Open the Extensions UI.
.. Look for plugins organized under subdirectories matching your extra catalog names.
--

[NOTE]
====
Plugins from extra catalog index images appear in the Extensions UI but do not install automatically.
To install a plugin from an extra catalog, you must add explicit configuration to your `dynamic-plugins.yaml` file.
====
