= The development toolchain

[role="_abstract"]
To develop custom plugins for {product} 2.1, set up a toolchain for the new front-end system (NFS). The tools create NFS plugins and package them for dynamic loading.

The following tools support the development workflow:

Node.js 22 and Yarn 4:: Run the version-pinned plugin project and manage its dependencies.

Container tools:: Use Podman or Docker to package exported plugins as OCI images and push them to a registry.

{product-very-short} CLI:: Use `npx @red-hat-developer-hub/cli@2.1.0 plugin new` to create a standalone plugin project with dependencies matched to {product} 2.1. Use `plugin export` and `plugin package` to prepare and distribute it. The 2.1 CLI creates standard module federation assets and NFS feature metadata; it does not generate Scalprum assets.

{product-local-very-short}:: Use the CLI `plugin dev` commands with a local {product-very-short} checkout to test an exported plugin in the application.

In a plugin generated by the 2.1 CLI, front-end plugin authors add extension blueprints to the `extensions` array in `src/plugin.tsx`. The plugin is the default export of `src/index.ts`. Administrators install the package and use `app.extensions` only when they need to override a discovered extension. For migration steps for existing plugins, see {configuring-book-link}#migrate-custom-plugins-to-ensure-compatibility-after-upgrade_migrate-to-the-front-end-system-to-use-blueprint-based-dynamic-routing[Migrate custom plugins to ensure compatibility after upgrade].
