= Front-end plugin wiring for extension-based customization

[role="_abstract"]
Front-end plugin wiring in {product} {product-version} uses extension blueprints so that you can control how dynamic plugins contribute pages, UI components, icons, and APIs to the application.

Plugins declare their extensions through a default-exported NFS feature at a package entry point by using typed blueprints, such as `PageBlueprint`, `EntityCardBlueprint`, and `IconBundleBlueprint`. A plugin generated by the 2.1 CLI uses the package root; an existing migrated plugin can use `./alpha`. The {product-short} application discovers and loads these extensions by default. Use the `app.extensions` section of your `{my-app-config-file}` file only to disable, reorder, or customize them.
