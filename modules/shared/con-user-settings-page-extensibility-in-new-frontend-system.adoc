= Extend user settings with custom configuration options

[role="_abstract"]
The user settings page supports plugin-contributed extensions that add custom tabs and configuration options.
This enables you to centralize all user-facing configuration in one location and provide consistent access to plugin-specific settings.

== What is user settings extensibility

User settings extensibility allows plugins to contribute new tabs, cards, and configuration sections to the user settings page.
Multiple plugins can contribute extensions simultaneously, and administrators control which extensions appear through the `app.extensions` section of the `{my-app-config-file}` file.

== Why centralize user settings

Centralizing user settings provides the following benefits:

* **Consistent location**: Users know where to find all configuration options
* **Reduced navigation**: No need to search through multiple menus for settings
* **Plugin integration**: Custom plugins can expose their settings in the standard location
* **Administrative control**: Administrators can hide or reorder settings tabs through configuration

== How user settings extensibility works

Plugins export settings extensions through their `/alpha` entry point using extension blueprints.
The user settings page discovers these extensions automatically and renders them as tabs or cards within tabs.
Administrators use the `app.extensions` configuration to control:

* Which settings tabs appear
* The order of tabs
* Tab titles and icons
* Which users can access specific settings tabs

== Default user settings tabs

{product} {product-version} provides the following default user settings tabs:

General:: User profile information and locale preferences
Authentication Providers:: Connected authentication providers and tokens
Feature Flags:: Toggle experimental features on or off

== Extension types for user settings

Plugins can contribute the following extension types:

Settings tabs:: New top-level tabs in the user settings navigation. Each tab can contain multiple cards or sections.
Settings cards:: Cards within a settings tab that group related configuration options.

== Auto-discovery of settings extensions

When a plugin with settings extensions is installed in the `dynamic-plugins-root` directory, {product} automatically discovers and loads the extensions.
No explicit configuration is required unless you want to customize the extension behavior or control visibility.

== Relationship to new front-end system

The user settings page is rebuilt in {product} {product-version} to support extension points in the new front-end system.
Settings extensions use blueprint patterns similar to entity page extensions, providing consistent configuration and behavior across the application.
