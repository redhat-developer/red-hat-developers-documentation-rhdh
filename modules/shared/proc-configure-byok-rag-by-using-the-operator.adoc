= Configure BYOK RAG by using the Operator

[role="_abstract"]
Deploy your BYOK container image as an init container and update `lightspeed-stack.yaml` to activate the custom knowledge source in your Operator-based {product} ({product-very-short}) deployment.

.Prerequisites
* You have packaged your vector database as a container image as described in xref:package-a-byok-rag-container-image_{context}[Package a BYOK RAG container image].
* You have the `vector_db_id` value from the generated `lightspeed-stack.yaml` snippet in your vector database output directory.
* The {product-very-short} Operator is installed on your cluster.
* You have cluster administrator privileges.
* The BYOK container image is accessible from your cluster.

.Procedure

. Create a `ConfigMap` containing your customized `lightspeed-stack.yaml`. Add the `byok_rag` section with the values from your generated vector database, and add your knowledge source to the `rag` section:
+
[source,yaml,subs="+attributes,+quotes"]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: lightspeed-stack-byok
data:
  lightspeed-stack.yaml: |
    name: Lightspeed Core Stack ({lcs-short})
    llama_stack:
      use_as_library_client: true  <1>
    byok_rag:
      - rag_id: custom-docs-1_0  <2>
        rag_type: inline::faiss
        embedding_model: sentence-transformers/all-mpnet-base-v2
        embedding_dimension: 768
        vector_db_id: <auto-generated-id>  <3>
        db_path: /app-root/byok-data/rag/vector_db/custom_docs/1.0/faiss_store.db  <4>
        score_multiplier: 1.0
    rag:
      tool:
        - custom-docs-1_0  <5>
----
+
<1>:: Do not change this value. Library mode is required for {product-very-short} deployments.
<2> Must match the `--index` value used when generating the vector database.
<3> Copy this value from the `vector_db_id` field in the generated `lightspeed-stack.yaml` file.
<4> Must match the path where the init container copies data.
<5> Must match `rag_id`. Use `rag.tool` to let the AI model retrieve from this source on-demand, or `rag.inline` to inject results into every prompt automatically.

. Apply the `ConfigMap` to your cluster:
+
[source,terminal]
----
$ oc apply -f lightspeed-stack-byok-configmap.yaml
----

. Update your `{backstage}` custom resource (CR) to mount the custom `ConfigMap`, add the BYOK init container, and configure the shared volume:
+
[source,yaml,subs="+attributes,+quotes"]
----
apiVersion: rhdh.redhat.com/v1alpha5
kind: {product-custom-resource-type}
metadata:
  name: lightspeed-rhdh
spec:
  application:
    extraFiles:
      configMaps:
        - name: "lightspeed-stack-byok"  <1>
          mountPath: /app-root
          key: lightspeed-stack.yaml
          containers:
            - lightspeed-core
    extraContainers:
      initContainers:
        - name: init-byok-custom-docs  <2>
          image: <registry>/<namespace>/byok-custom-docs:1.0
          command: ["cp", "-r", "/rag/.", "/byok-data/"]
          volumeMounts:
            - name: byok-data
              mountPath: /byok-data
    extraVolumes:
      - name: byok-data
        emptyDir: {}
    extraVolumeMounts:
      - name: byok-data
        mountPath: /app-root/byok-data
        containers:
          - lightspeed-core
----
+
<1>:: References the `ConfigMap` created in the previous step. This replaces the default `lightspeed-stack.yaml` for the `lightspeed-core` container.
<2> The init container runs before {lcs-name} starts and copies the vector database to the shared `EmptyDir` volume.

. Apply the updated `{backstage}` CR:
+
[source,terminal]
----
$ oc apply -f <backstage_cr_file>.yaml
----
