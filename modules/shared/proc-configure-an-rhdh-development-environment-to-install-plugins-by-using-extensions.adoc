= Configure persistent storage for plugin installations

[role="_abstract"]
To retain plugins installed through the Extensions UI across application restarts, configure persistent storage for the dynamic plugin cache. A persistent volume claim (PVC) stores the Extensions configuration file.

[IMPORTANT]
====
Installing plugins through Extensions is supported only in development environments. The Extensions interface prevents plugin installations in production environments.
====

For more information about the dynamic plugins cache, see {configuring-book-link}#using-the-dynamic-plugins-cache_running-behind-a-proxy[Using the dynamic plugins cache].

.Prerequisites
* You have created a persistent volume claim (PVC) for the dynamic plugins cache with the name *dynamic-plugins-root*.
* You have installed {product} using the Helm chart or the Operator.
* You have installed the OpenShift CLI (`oc`).

.Procedure
. Create the extensions configuration file and save it as `dynamic-plugins.extensions.yaml`. For example:
+
[source,yaml]
----
includes:
  - dynamic-plugins.default.yaml

plugins:
  - package: ./dynamic-plugins/dist/red-hat-developer-hub-backstage-plugin-extensions
    enabled: true
  - package: ./dynamic-plugins/dist/red-hat-developer-hub-backstage-plugin-extensions-backend-dynamic
    enabled: true
    pluginConfig:
      extensions:
        installation:
          enabled: true
          saveToSingleFile:
            file: /opt/app-root/src/dynamic-plugins-root/dynamic-plugins.extensions.yaml
----
+
The Extensions front-end plugin provides its page, sidebar item, and translations through the new front-end system. You do not need to add `dynamicPlugins.frontend` entries for these features.

. Copy the file to your cluster by running the following commands:
+
[source,yaml]
----
oc get pods -n <your_namespace>

oc cp ./dynamic-plugins.extensions.yaml <your_namespace>/<pod_name>:/opt/app-root/src/dynamic-plugins-root/dynamic-plugins.extensions.yaml
----

. Update your {product-very-short} application to use this file:
.. For operator-based installations:
//... Click on the overflow menu...
... Update your {product-custom-resource-type} CR to update the `NODE_ENV` environment variable  to `development`, as follows:
+
[source,yaml,subs="+attributes"]
----
apiVersion: rhdh.redhat.com/v1alpha5
kind: {product-custom-resource-type}
metadata:
  name: developer-hub
  namespace: rhdh
spec:
  application:
    dynamicPluginsConfigMapName: dynamic-plugins-rhdh
    extraEnvs:
      envs:
        - name: NODE_ENV
          value: "development"
      secrets:
        - name: secrets-rhdh
    extraFiles:
      mountPath: /opt/app-root/src
    route:
      enabled: true
  database:
    enableLocalDb: true
----
... Update your `dynamic-plugins-rhdh` config map to include your extensions configuration file, as follows:
+
[source,yaml]
----
kind: ConfigMap
apiVersion: v1
metadata:
  name: dynamic-plugins-rhdh
  namespace: rhdh
data:
 dynamic-plugins.yaml: |
   includes:
     - dynamic-plugins.default.yaml
     - /dynamic-plugins-root/dynamic-plugins.extensions.yaml
   plugins: []
----


.. For Helm chart installations:

... Upgrade the Helm release to include your extensions configuration file and update the `NODE_ENV` environment variable  to `development`:
+
[source,yaml]
----
auth:
  backend:
    enabled: true
openshift:
  clusterRouterBase: apps.<clusterName>.com
dynamicPlugins:
  includes:
    - dynamic-plugins.default.yaml
    - /dynamic-plugins-root/dynamic-plugins.extensions.yaml
extraEnv:
  - name: NODE_ENV
    value: development
----
... Click *Upgrade*

.Verification
Enable a plugin by using the Extensions UI, restart your {product-very-short} application, and refresh the UI to confirm that you enabled the plugin.
