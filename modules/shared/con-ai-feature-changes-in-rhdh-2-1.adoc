= AI feature changes in {product-very-short} 2.1

[role="_abstract"]
{product} ({product-very-short}) 2.1 introduces changes to the AI backend infrastructure, safety configuration, and permission model that affect your {ia-name} ({ia-short}) configuration.

Infrastructure naming changes::

{product-very-short} 2.1 replaces the Llama Stack backend with {lcs-name} ({lcs-short}). If your deployment uses custom configuration files or Kubernetes resources with Llama Stack names, you must update them:

* The backend container is renamed from `llama-stack` to `lightspeed-core`.
* The backend runs from the `lightspeed-core/lightspeed-stack-rhel9` image.
* Backend configuration moves from the Llama Stack `run.yaml` file to the `lightspeed-stack.yaml` file, which {lcs-short} reads from a config map. You no longer edit the generated `run.yaml` file.

Safety guard changes::

{product-very-short} 2.1 replaces the Llama Guard safety provider, registered shield resources, and `run.yaml` overrides with a single question-validity shield that {lcs-short} defines in `lightspeed-stack.yaml`. You enable or disable the shield through environment variables in the Kubernetes Secret that {lcs-short} reads, rather than through a separate image or `run.yaml` edits.

Permission model changes::

{product-very-short} 2.1 replaces the `lightspeed.{asterisk}` permission identifiers with behavior-linked names that use the `intelligent-assistant.{asterisk}` and `mcp.{asterisk}` namespaces. This is a breaking change. For the full list of new permissions and a migration table from previous names, see "AI feature permissions" in Additional resources.
