= Configure {product} to authenticate {product-cli}

[role="_abstract"]
To sign in to a {product} instance from {product-cli}, enable the authentication plugin. The CLI uses OAuth2 flows to obtain and refresh tokens.

[IMPORTANT]
====
Old front-end system (OFS) configuration examples do not apply to {product} 2.1, and direct replacements might not exist for every option. In {product} 2.1, the new front-end system removes the previous `dynamicPlugins.frontend` configuration. The plugin provides the `/oauth2/*` route for the consent flow through extension blueprints, so you do not wire it manually.

For documented configuration changes, see {configuring-book-link}#configuration-key-mapping-from-old-to-new-front-end-system_migrate-to-the-front-end-system-to-use-blueprint-based-dynamic-routing[Configuration key mapping from old to new front-end system]. If you develop custom plugins, see {configuring-book-link}#migrate-custom-plugins-to-ensure-compatibility-after-upgrade_migrate-to-the-front-end-system-to-use-blueprint-based-dynamic-routing[Migrate custom plugins to ensure compatibility after upgrade].
====

.Prerequisites
* You are running {product} ({product-very-short}) 2.1 or later.
* You have installed {product-cli} 2.0.9 or later.
* You have administrative access to the {product-very-short} configuration.
* You can install dynamic plugins on your instance.

.Procedure
. Install the `backstage-plugin-auth` front-end plugin as a dynamic plugin so that your instance can serve the OAuth2 consent page. Add the following entry to your `dynamic-plugins.yaml` file:
+
[NOTE]
====
The plugin image tag in the following example is published for {product} 2.1 and built against {backstage} 1.54.9. For any new {product-very-short} release, use a plugin image built for that release's {backstage} version.
====
+
[source,yaml]
----
plugins:
  - package: 'oci://ghcr.io/redhat-developer/rhdh-plugin-export-overlays/backstage-plugin-auth:bs_1.54.9__0.1.11'
    enabled: true
----
+
The plugin provides the `/oauth2/*` consent route that the sign-in flow requires through extension blueprints, so you do not wire it manually.
+
For more information about installing dynamic plugins, see {installing-and-viewing-plugins-book-link}[{installing-and-viewing-plugins-book-title}].

. In your `app-config` file, enable the OAuth2 client ID metadata documents and refresh token flows that the CLI requires:
+
[source,yaml]
----
auth:
  clientIdMetadataDocuments:
    enabled: true
  experimentalRefreshToken:
    enabled: true
----
+
[NOTE]
====
The `clientIdMetadataDocuments` key applies to {backstage} 1.53 and later, which {product} 2.1 uses. On earlier versions, use `experimentalClientIdMetadataDocuments`, which remains available as a deprecated alias in later releases.
====

. Save the file and restart your instance to apply the configuration.

.Verification
* Sign in from the CLI as described in xref:authenticating-and-registering-action-sources-for-the-rhdh-cli_{context}[Authenticate and register action sources]. A successful login confirms that {product-very-short} accepts the CLI authentication flows.
