= The dynamic plugin factory model

[role="_abstract"]
To convert standard {product-custom-resource-type} plugins into {product-very-short} dynamic plugins, use the {product-very-short} Dynamic Plugin Factory. The factory automates plugin export and packaging.

For {product} 2.1, a custom front-end plugin must default-export a new front-end system (NFS) feature from a package entry point before the factory or CLI packages it. The CLI detects the feature and records its entry point in `backstage.features`. A plugin generated by the 2.1 CLI uses the package root; an existing migrated plugin can use a separate `./alpha` entry point. Migrate the source plugin to extension blueprints before building its dynamic package.

[IMPORTANT]
====
{company-name} maintains the Dynamic Plugin Factory as an open source project, but does not support it or subject it to any service level agreement (SLA).
====

Manually converting {product-custom-resource-type} plugins to {product-very-short} dynamic plugins requires configuring webpack, managing dependencies, and building container images. This process can be both time-consuming and error-prone. The Dynamic Plugin Factory automates this entire workflow, providing a reproducible way to convert plugins from source code to deployable containers without requiring deep knowledge of build tools.

This approach is particularly valuable when you are:

* Converting multiple community plugins from the {product-custom-resource-type} marketplace.
* Testing custom plugin changes during active development.
* Ensuring consistent builds across development teams.
* Applying patches to plugin source code before building.

== How the Dynamic Plugin Factory works

The core function of the Dynamic Plugin Factory tool is to streamline the dynamic plugin build process, offering the following capabilities:

Source repository management:: Clones and checks out plugin source repositories.
Multi-workspace support:: Exports plugins from multiple workspaces across different repositories in a single run.
Patch and overlay system:: Applies custom modifications to plugin source code before exporting.
Dependency management:: Automates yarn installation with TypeScript compilation, and automated private dependency handling for backend dynamic plugins.
Dynamic plugin packaging:: Builds, exports, and packages plugins by using the {product-very-short} CLI.
Container image publishing:: Optionally pushes to container registries such as Quay or OpenShift.

The Dynamic Plugin Factory gives developers and platform engineers a reproducible way to create and test dynamic plugins. Its preconfigured container and documentation help with migration and testing.
