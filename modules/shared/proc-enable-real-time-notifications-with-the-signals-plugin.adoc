= Enable real-time notifications with the signals plugin

[role="_abstract"]
Enable the Signals plugin so that your team receives updates instantly in {product} ({product-very-short}) instead of waiting for the next polling interval.

Plugins such as Notifications poll for new events periodically, which can delay delivery by several seconds. Enabling Signals removes that delay so your team can act on workflow events, template updates, and other changes as they happen.

.Prerequisites

* You have {configuring-book-link}[added a custom {product-short} application configuration].
* You have installed and enabled at least one plugin that uses Signals, such as the Notifications plugins:
** `backstage-plugin-notifications`
** `backstage-plugin-notifications-backend-dynamic`

.Procedure

. Open your {product-very-short} dynamic plugin configuration file.
. Add the Signals frontend and backend plugins:
+
[source,yaml]
----
plugins:
  - package: ./dynamic-plugins/dist/backstage-plugin-signals
    disabled: false
  - package: ./dynamic-plugins/dist/backstage-plugin-signals-backend-dynamic
    disabled: false
----
. Optional: To publish signals over HTTP, add the `signals` topic to your `app-config.yaml` file:
+
[source,yaml]
----
events:
  http:
    topics:
      - signals
----
. Save the configuration file and restart your {product-very-short} instance.

.Verification

. Log in to your {product} instance.
. Trigger an event from a plugin that uses Signals, such as updating a Software Template version.
. Verify that the update appears in the {product-very-short} header without requiring a page refresh.
