= Dynamic front-end plugins for controlled UI extensibility

[role="_abstract"]
You can choose which dynamic front-end plugin features are active in your {product-short} application by configuring extension blueprints.

Each plugin exports its UI contributions through the `/alpha` entry point, and you control availability and behavior through the `app.extensions` section of your `{my-app-config-file}` file.

[cols="1,1,2"]
|===
|Scenario|Extension blueprint|Description

|Adding entity page content
|`EntityContentBlueprint`
|Add or customize a tab on the *Catalog entity* view.

|Adding entity page cards
|`EntityCardBlueprint`
|Add a card to an entity page section.

|Adding new pages
|`PageBlueprint`
|Add a new page and route to the application. For example, `/my-plugin`. Sidebar navigation entries are inferred automatically from page extensions.

|Registering icons
|`IconBundleBlueprint`
|Add custom icons to the application catalog.

|Providing APIs
|`ApiBlueprint`
|Supply a custom utility API implementation or override an existing one.

|Adding translation resources
|`TranslationBlueprint`
|Provide translation files or override default plugin translations.
|===

== Entity page customization examples

The `EntityCardBlueprint` and `EntityContentBlueprint` provide fine-grained control over entity pages.

Use `EntityCardBlueprint` to add cards to entity page sections:

[source,yaml]
----
app:
  extensions:
    # Add a monitoring card to the overview tab
    - entity-card:monitoring-plugin/overview-card:
        config:
          filter: kind:component  # Show only for components
          title: "Service Health"

    # Add a security card filtered by namespace
    - entity-card:security-plugin/vulnerability-scan:
        config:
          filter: kind:component,metadata.namespace:production
          title: "Security Scan Results"
----

Filter expressions support the following criteria:

* `kind:<entity-kind>` - Filter by entity kind (component, api, system, etc.)
* `metadata.namespace:<namespace>` - Filter by entity namespace
* Multiple filters separated by commas combine with AND logic

Use `EntityContentBlueprint` to add tabs to entity pages with custom titles, icons, and grouping:

[source,yaml]
----
app:
  extensions:
    # Add a custom deployment tab
    - entity-content:deployment-plugin/deployments:
        config:
          title: "Deployments"
          filter: kind:component
          icon: deployment

    # Add a compliance tab with group navigation
    - entity-content:compliance-plugin/compliance-status:
        config:
          title: "Compliance"
          filter: kind:component,kind:api
          icon: security
----

== Auto-discovery for entity extensions

{product} automatically discovers entity extensions from installed dynamic plugins.
When a plugin is installed in the `dynamic-plugins-root` directory and exports entity card or entity content extensions, they appear automatically on matching entity pages.

You can control extension behavior through the `app.extensions` configuration:

* Disable extensions by setting them to `false`
* Customize titles, icons, and filters through the `config` section
* Control display order by listing extensions in your desired order

[id="operator-configuration-for-extensions_{context}"]
== Operator configuration for extensions

Plugins declare their extension defaults in code. Extensions from an installed plugin are auto-discovered and loaded by default. As an operator, you use the `app.extensions` section in your `{my-app-config-file}` file to disable, reorder, or override extension configuration:

[source,yaml]
----
app:
  extensions:
    - entity-card:my-plugin/my-component:
        config:
          filter: kind:Component
    - entity-card:my-plugin/unused-component: false
----
