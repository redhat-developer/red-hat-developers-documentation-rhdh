= Configure BYOK RAG by using the Helm chart

[role="_abstract"]
Deploy your BYOK container image as an init container and register the custom knowledge source in `lightspeed-stack.yaml` in your Helm-based {product} ({product-very-short}) deployment.

.Prerequisites
* You have packaged your vector store as a container image as described in xref:package-a-byok-rag-container-image_{context}[Package a BYOK RAG container image].
* You have the generated `vector_db_id` value from xref:generate-a-vector-database-for-byok-rag_{context}[Generate a vector database for BYOK RAG].
* You have access to a running {product-very-short} instance deployed with the Helm chart.
* The BYOK container image is accessible from your cluster.

.Procedure

. Create a `ConfigMap` that contains your customized `lightspeed-stack.yaml`. Add the `sentence_transformers` embedding provider, register the store under `rag.byok.stores`, and activate it under `rag.retrieval`:
+
[source,yaml,subs="+attributes,+quotes"]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: lightspeed-stack-byok
data:
  lightspeed-stack.yaml: |
    inference:
      providers:
        - type: sentence_transformers
    rag:
      byok:
        stores:
          - rag_id: custom-docs  <1>
            backend: faiss
            embedding_model: sentence-transformers/all-mpnet-base-v2
            embedding_dimension: 768
            vector_db_id: vs_replace_with_generated_id  <2>
            db_path: /rag-content/vector_db/custom_docs/faiss_store.db  <3>
            score_multiplier: 1.0  # Used by Inline RAG only
      retrieval:
        tool:
          sources:
            - custom-docs  <4>
----
+
<1>:: The `rag_id` identifies the retrieval source. Use the same value under `rag.retrieval.tool.sources`.
<2> Replace with the `vector_db_id` value that you read from the generated `llama-stack.yaml` file. The runtime configuration must use the exact same ID.
<3> Must match the path where the init container copies the database inside the {ia-short} container.
<4> Must match `rag_id`. If you have other sources, such as product documentation, list each required source under `sources`.

. Apply the `ConfigMap` to your cluster:
+
[source,terminal]
----
$ kubectl apply -f lightspeed-stack-byok-configmap.yaml
----

. Update your Helm `values.yaml` file to reference the custom `ConfigMap`, add the BYOK init container, and configure the shared volume:
+
[source,yaml]
----
global:
  lightspeed:
    configMaps:
      - name: stack
        create: false
        nameOverride: "lightspeed-stack-byok"  <1>
        mountPath: /app-root/lightspeed-stack.yaml
        subPath: lightspeed-stack.yaml
        sourceFile: lightspeed-stack.yaml
        optional: false
    extraInitContainers:  <2>
      - name: byok-rag-init
        image: quay.io/your-organization/rhdh-byok:1.0.0
        command: ["/bin/sh", "-c"]
        args:
          - |
            set -eu
            mkdir -p /rag-content/vector_db
            cp -R /byok/vector_db/. /rag-content/vector_db/
        volumeMounts:
          - name: lightspeed-rag
            mountPath: /rag-content
    extraVolumes:
      - name: lightspeed-rag
        emptyDir: {}
    extraVolumeMounts:
      - name: lightspeed-rag
        mountPath: /rag-content
        containers:
          - lightspeed-core
----
+
<1>:: Replace the default `lightspeed-stack.yaml` `ConfigMap` with your custom one that contains the BYOK configuration.
<2> The init container runs before {ia-short} starts and copies the vector database to the shared volume.

. Run `helm upgrade` to apply the changes:
+
[source,terminal,subs="+attributes"]
----
$ helm upgrade <release-name> redhat-developer-hub \
    --repo https://charts.openshift.io/ \
    --version {product-chart-version} \
    -f values.yaml
----
