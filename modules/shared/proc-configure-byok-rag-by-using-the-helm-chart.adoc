= Configure BYOK RAG by using the Helm chart

[role="_abstract"]
Deploy your BYOK container image as an init container and update `lightspeed-stack.yaml` to activate the custom knowledge source in your Helm-based {product} ({product-very-short}) deployment.

.Prerequisites
* You have packaged your vector database as a container image as described in xref:package-a-byok-rag-container-image_{context}[Package a BYOK RAG container image].
* You have the `vector_db_id` value from the generated `lightspeed-stack.yaml` snippet in your vector database output directory.
* You have access to a running {product-very-short} instance deployed with the Helm chart.
* The BYOK container image is accessible from your cluster (in your registry or mirrored for air-gapped deployments).

.Procedure

. Create a `ConfigMap` containing your customized `lightspeed-stack.yaml`. Add the `byok_rag` section with the values from your generated vector database, and add your knowledge source to the `rag` section:
+
[source,yaml,subs="+attributes,+quotes"]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: lightspeed-stack-byok
data:
  lightspeed-stack.yaml: |
    name: Lightspeed Core Stack ({lcs-short})
    llama_stack:
      use_as_library_client: true  <1>
    byok_rag:
      - rag_id: custom-docs-1_0  <2>
        rag_type: inline::faiss
        embedding_model: sentence-transformers/all-mpnet-base-v2
        embedding_dimension: 768
        vector_db_id: <auto-generated-id>  <3>
        db_path: /app-root/byok-data/rag/vector_db/custom_docs/1.0/faiss_store.db  <4>
        score_multiplier: 1.0
    rag:
      tool:
        - custom-docs-1_0  <5>
----
+
<1>:: Do not change this value. Library mode is required for {product-very-short} deployments.
<2> Must match the `--index` value used when generating the vector database.
<3> Copy this value from the `vector_db_id` field in the generated `lightspeed-stack.yaml` file.
<4> Must match the path where the init container copies data. If your init container copies to `/byok-data/` with the command `cp -r /rag/. /byok-data/`, the path is `/app-root/byok-data/rag/vector_db/custom_docs/1.0/faiss_store.db`.
<5> Must match `rag_id`. Use `rag.tool` to let the AI model retrieve from this source on-demand, or `rag.inline` to inject results into every prompt automatically.

. Apply the `ConfigMap` to your cluster:
+
[source,terminal]
----
$ kubectl apply -f lightspeed-stack-byok-configmap.yaml
----

. Update your Helm `values.yaml` file to reference the custom `ConfigMap` and add the BYOK init container:
+
[source,yaml]
----
global:
  lightspeed:
    configMaps:
      - name: stack
        create: false
        nameOverride: "lightspeed-stack-byok"  <1>
        mountPath: /app-root/lightspeed-stack.yaml
        subPath: lightspeed-stack.yaml
        sourceFile: lightspeed-stack.yaml
        optional: false
    extraInitContainers:  <2>
      - name: init-byok-custom-docs
        image: <registry>/<namespace>/byok-custom-docs:1.0
        command: ["cp", "-r", "/rag/.", "/byok-data/"]
        volumeMounts:
          - name: byok-data
            mountPath: /byok-data
    extraVolumes:
      - name: byok-data
        emptyDir: {}
    extraVolumeMounts:
      - name: byok-data
        mountPath: /app-root/byok-data
        containers:
          - lightspeed-core
----
+
<1>:: Replace the default `lightspeed-stack.yaml` ConfigMap with your custom one containing the `byok_rag` configuration.
<2> The init container runs before {lcs-name} starts and copies the vector database to the shared volume. Only modify the `create` and `nameOverride` fields in the `configMaps` entry.

. Run `helm upgrade` to apply the changes:
+
[source,terminal]
----
$ helm upgrade <release-name> redhat-developer-hub \
    --repo https://charts.openshift.io/ \
    --version {product-chart-version} \
    -f values.yaml
----
