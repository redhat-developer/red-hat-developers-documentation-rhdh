= {ia-brand-name} architecture for your AI backend deployment

[role="_abstract"]
Review the {ia-name} component architecture to plan your system layout and coordinate connections with your artificial intelligence (AI) backend deployment.

The architecture relies on the {lcs-name} ({lcs-short}) container, which operates as the primary intermediary layer to manage {ia-name} functionality and console user interactions. After you enable the plugin, the interface appears as the *Intelligent Assistant* button on all platforms that host {product-very-short}.

{ia-name} connects only to {lcs-short}. {lcs-short} manages the configuration for the model inference, query validation, tool calling, and the vector store. You configure these capabilities through {lcs-short}, and {ia-name} consumes them through {lcs-short} APIs.

{ogx-name} ({ogx-short}) is an internal implementation detail of {lcs-short} and is not a customer-facing component. Do not configure {ogx-short} directly, call {ogx-short} APIs, or edit the generated `/tmp/.generated/run.yaml` file. Configure {lcs-short} instead, so that your deployment stays stable across {ogx-short} changes.
