= {ls-brand-name} architecture for your AI backend deployment

[role="_abstract"]
Review the {ls-short} component architecture to plan your system layout and coordinate connections with your artificial intelligence (AI) backend deployment.

The architecture relies on the {lcs-name} ({lcs-short}) container, which operates as the primary intermediary layer to manage {ls-short} functionality and console user interactions. After you enable the plugin, the interface is displayed as the *Intelligent Assistant* button on all platforms that host {product-very-short}.

{ls-short} connects only to {lcs-short}. {lcs-short} owns the model inference, prompt validation, tool calling, and vector-store configuration for your deployment. You configure these capabilities through {lcs-short}, and {ls-short} consumes them through {lcs-short} APIs.

Llama Stack is an internal implementation detail of {lcs-short} and is not a customer-facing component. Do not configure Llama Stack directly, call Llama Stack APIs, or edit the generated `/tmp/.generated/run.yaml` file. Configure {lcs-short} instead, so that your deployment stays stable across Llama Stack changes.
