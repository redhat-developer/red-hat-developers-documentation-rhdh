= Front-end extension loading in {product} 2.1

[role="_abstract"]
In {product} 2.1, the application discovers and loads extensions from an installed front-end plugin by default. You do not need to add `dynamicPlugins.frontend` wiring for routes, mount points, or APIs.

If a custom front-end plugin does not appear, check these conditions:

Plugin installation:: Verify that you have installed and enabled the plugin package.
Migration:: Verify that a package entry point default-exports a new front-end system feature. A plugin generated by the 2.1 CLI uses the package root; an existing migrated plugin can use `./alpha`. A plugin that uses only the old front-end system does not load in {product} 2.1.
Extension overrides:: Check `app.extensions` for an entry that disables or changes the expected extension.

[TIP]
====
Check the backend logs for a missing-manifest error. If the application loads the plugin remotely but does not display its feature, check the browser developer console for a skipped `FrontendFeature` export. For migration steps, see {configuring-book-link}#migrate-custom-plugins-to-ensure-compatibility-after-upgrade_migrate-to-the-front-end-system-to-use-blueprint-based-dynamic-routing[Migrate custom plugins to ensure compatibility after upgrade].
====
