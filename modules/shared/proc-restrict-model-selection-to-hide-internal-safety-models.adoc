= Restrict model selection to hide internal safety models

[role="_abstract"]
To prevent users from selecting internal safety models in the chat dialog, restrict the models available in the model selection dropdown menu by defining an allowlist for each inference provider in the `config.yaml` Llama Stack configuration file.

By default, the model selection dropdown menu lists every model that the configured inference provider exposes, including internal safety models such as Llama Guard that are not intended for end-user prompts. Selecting these models is prone to user error during workshops and standard workflows.

To restrict the list, set the `allowed_models` field under `config` for each inference provider in the `config.yaml` file. When you define `allowed_models`, the dropdown menu shows only the listed models, so users see only the functional, user-facing models that you allow.

.Prerequisites
* You have access to the `config.yaml` Llama Stack configuration file for your deployment.

.Procedure
. In the `config.yaml` file, add the `allowed_models` field under `config` for each inference provider, and list the models that you want to expose to users:
+
[source,yaml]
----
version: 3
distro_name: developer-lightspeed-lls-0.5.x
# ...
providers:
  # ...
  inference:
    - provider_id: ${env.ENABLE_OLLAMA:+ollama}
      provider_type: remote::ollama
      config:
        base_url: ${env.OLLAMA_URL:=http://localhost:11434/v1}
        allowed_models:
          - llama3.1
    - provider_id: ${env.ENABLE_OPENAI:+openai}
      provider_type: remote::openai
      config:
        api_key: ${env.OPENAI_API_KEY:=}
        allowed_models:
          - gpt-4o-mini
          - gpt-4.1-mini
          - gpt-4.1-nano
----
+
where:
+
`allowed_models`:: The list of models that appear in the model selection dropdown menu for that provider. Models that you omit from this list, including internal safety models, are hidden from users.

. Apply the updated `config.yaml` file by adding it as a config map and mounting it to your Llama Stack container so that it overrides the default image file. For more information, see xref:configure-safety-guards-in-rhdh_{context}[Configure safety guards in {product}].

. Restart the deployment if it does not trigger an automatic rollout.

.Verification
. Log in to your {product-very-short} instance.
. Open the chat dialog and select the model selection dropdown menu.
. Confirm that the dropdown menu lists only the allowed models and that internal safety models are hidden.
