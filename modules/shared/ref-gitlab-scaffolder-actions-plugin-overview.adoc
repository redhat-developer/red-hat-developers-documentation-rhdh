= GitLab scaffolder actions plugin overview

Use the `gitlab-scaffolder-actions` plugin to customize your scaffolder template with various GitLab-specific actions. By configuring the actions, you can utilize them in many different scenarios.

publish::
* Initializes a git repository with the content in the workspace, and publishes it to GitLab with the default configuration.
* Adds a description.
* Initializes a repository with an initial commit message (if not set, the message defaults to `initial commit`).
* Initializes a repository with additional settings.
* Initializes a repository with fast forward merge and "always squash" settings.
* Initializes a repository with branch settings.
* Initializes a repository with environment variables.
* Initializes a repository with pipeline must succeed and allow merge on skipped pipeline settings.
* Initializes a repository with setting to require all threads (discussions) on merge request to be resolved before merging.
* Initializes a repository with the default `README` file and no files from workspace (only if this repository does not exist yet).
* Initializes a repository with a custom project title that differs from the repository slug.
* Initializes a repository and adds a specific user as project owner.

gitlabGroup::
* Creates a group at the top level, with a description.
* Creates a group nested within another group.
* Creates a group nested within multiple other groups.
* Creates a group in dry run mode.
* Creates a group nested within another group using objects.
* Creates a group nested within another group using path and objects.

gitlabGroupAccess::
* Adds users to a group using numeric group ID.
* Adds users to a group using string path.
* Removes users from a group.
* Shares or unshares a group.

gitlabIssue::
* Creates or edits an issue.
* Creates or edits an issue with assignees and date options.
* Creates an issue with a token.
* Creates or edits an issue with a specific milestone and weight.
* Creates an issue to resolve a discussion in a merge request.
* Edits the state of an issue.
* Edits issue type.
* Edits issue labels.
* Locks discussion in an issue.
* Makes an issue confidential.

createMergeRequest::
* Creates a merge request with a target branch.
* Creates a merge request with a specific assignee.
* Creates a merge request with automatic removal of source branch after merge.
* Creates a merge request with the *create*, *delete* or *update* commit actions.

triggerPipeline::
* Triggers a Project pipeline without variables.
* Triggers a Project pipeline with single or multiple variables.

createAccessToken::
* Creates a project access token with minimal options.
* Creates a project access token with multiple options.
* Creates a project access token with custom scopes.
* Creates a project access token with a specified name.
* Creates a project access token with a numeric project ID.
* Creates a project access token with a specified expiration date.
* Creates a project access token with a specified access level.
* Creates a project access token with a token for authorization.
* Creates a project access token with read-only scope.
* Creates a project access token for a specific GitLab instance.

createDeployToken::
* Creates a project deploy token with minimal options.
* Creates a project deploy token with many custom scopes.
* Creates a project deploy token with a specified name.
* Creates a project deploy token with a numeric project ID.
* Creates a project deploy token with a custom username.

importGitLabRepo::
* Imports a repository from a remote GitLab instance.

createVariable::
* Creates an `env_var` project variable.
* Creates a `file` project variable.
* Creates a project variable that is protected.
* Creates a project variable with masked flag `true`.
* Creates a project variable that is expandable.
* Creates a project variable with a specific environment scope.
* Creates a project variable with a wildcard environment scope.

pushChanges::
* Pushes changes to a repository with minimal changes.
* Pushes changes to a repository with a specific source and target path.
* Pushes changes to a repository with a specific commit action.
* Pushes an empty commit to a repository (available from GitLab version 18.8).

gitlabUserInfo::
* Retrieves current authenticated user information.
* Retrieves user information by user ID.
* Retrieves user information with a custom token.
* Retrieves user information from a self-hosted GitLab instance.

.Example of a GitLab fetch and group actions in a Scaffolder template
[source,yaml]
----
  steps:
    - id: fetch
      name: Fetch
      action: fetch:template
      input:
        url: https://github.com/TEMPLATE
        values:
          name: ${{ parameters.name }}

    - id: createGitlabGroup
      name: Ensure Gitlab group exists
      action: gitlab:group:ensureExists
      input:
        repoUrl: ${{ parameters.repoUrl }}
        path:
          - path
          - to
          - group

----
