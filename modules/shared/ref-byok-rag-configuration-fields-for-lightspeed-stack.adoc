= BYOK RAG configuration fields for `lightspeed-stack.yaml`

[role="_abstract"]
Reference the `byok_rag` and `rag` fields available in `lightspeed-stack.yaml` to configure custom knowledge sources for {ls-short}.

[NOTE]
====
In {product} ({product-very-short}) deployments, {lcs-name} ({lcs-short}) runs in library mode. The `enrich_byok_rag()` function automatically generates all required Llama Stack vector I/O configuration from the `byok_rag` section. You only need to edit `lightspeed-stack.yaml` — do not edit `run.yaml`.
====

== `byok_rag` list fields

Each entry in the `byok_rag` list defines one custom knowledge source. You can define multiple sources.

[cols="1,1,1,3",options="header"]
|===
| Field | Type | Required | Description

| `rag_id`
| String
| Yes
| Unique identifier for this knowledge source. Must match the `--index` (`-i`) value used during vector database generation. Referenced in the `rag` section to activate the source.

| `rag_type`
| String
| Yes
| Vector store backend type. Use `inline::faiss` for all {product-very-short} deployments.

| `embedding_model`
| String
| Yes
| HuggingFace model ID for the embedding model. Must exactly match the `--model-name` (`-mn`) value used during vector database generation. Default: `sentence-transformers/all-mpnet-base-v2`.

| `embedding_dimension`
| Integer
| Yes
| Output dimension of the embedding model. For `sentence-transformers/all-mpnet-base-v2`, use `768`.

| `vector_db_id`
| String
| Yes
| Unique store identifier auto-generated during vector database creation. Copy this value from the `vector_db_id` field in the generated `lightspeed-stack.yaml` snippet found in your vector database output directory.

| `db_path`
| String
| Yes
| Absolute path to the `faiss_store.db` file within the `lightspeed-core` container. Must match the volume mount path from your init container. Example: `/app-root/byok-data/rag/vector_db/custom_docs/1.0/faiss_store.db`.

| `score_multiplier`
| Float
| No
| Relative priority weight applied to results from this source when multiple sources are configured. A higher value increases the ranking of retrieved results from this source. Default: `1.0`.
|===

== `rag` section fields

The `rag` section activates configured BYOK sources and sets the retrieval mode.

[cols="1,3",options="header"]
|===
| Field | Description

| `rag.tool`
| List of `rag_id` values for knowledge sources offered to the AI model as callable tools. The model retrieves from these sources on-demand when it determines retrieval is relevant. Recommended for most deployments — responses include tool-call transparency cards.

| `rag.inline`
| List of `rag_id` values for knowledge sources whose results are automatically injected into every prompt context before the model responds. Use when you always want retrieval to occur regardless of model judgment.
|===

== Example: Single source

[source,yaml]
----
byok_rag:
  - rag_id: custom-docs-1_0
    rag_type: inline::faiss
    embedding_model: sentence-transformers/all-mpnet-base-v2
    embedding_dimension: 768
    vector_db_id: <auto-generated-id>
    db_path: /app-root/byok-data/rag/vector_db/custom_docs/1.0/faiss_store.db

rag:
  tool:
    - custom-docs-1_0
----

== Example: Multi-source with priority ordering

[source,yaml]
----
byok_rag:
  - rag_id: product-docs-1_0
    rag_type: inline::faiss
    embedding_model: sentence-transformers/all-mpnet-base-v2
    embedding_dimension: 768
    vector_db_id: <auto-generated-id-1>
    db_path: /app-root/byok-data/rag/vector_db/product-docs/1.0/faiss_store.db
    score_multiplier: 1.5  <1>
  - rag_id: runbooks-1_0
    rag_type: inline::faiss
    embedding_model: sentence-transformers/all-mpnet-base-v2
    embedding_dimension: 768
    vector_db_id: <auto-generated-id-2>
    db_path: /app-root/byok-data/rag/vector_db/runbooks/1.0/faiss_store.db
    score_multiplier: 1.0

rag:
  tool:
    - product-docs-1_0
    - runbooks-1_0
----
+
<1>:: A higher `score_multiplier` value gives this source's results higher priority when {lcs-short} merges results from both sources.
