= Configure an aggregation card with a scalar tracking type

[role="_abstract"]
Configure a scorecard aggregation card to roll up a single numeric metric across your owned entities by using a scalar tracking type: `sum`, `average`, `max`, `min`, or `count`.

The following steps configure the card on a read-only home page. On a customizable home page, you do not define a `widgetLayout` section; instead, you add the card from the user interface and set its aggregation ID. For more information, see {scorecard-plugin-book-link}#configure-portfolio-health-on-a-customizable-home-page_configure-portfolio-health[Configure on a customizable home page].

.Prerequisites
* The scorecard plugin is installed and configured in your {product} instance.
* The metric that you want to aggregate returns a number value.
* You configured the dynamic home page layout and registered the aggregated Scorecard card in the `homepage.defaultWidgets` section. For more information, see {scorecard-plugin-book-link}#configure-a-default-scorecard-aggregation-card_configure-aggregated-scorecard-kpis[Configure a default scorecard aggregation card].

.Procedure

. Open your `app-config.yaml` file.

. Go to the `scorecard` section and define your backend key performance indicator (KPI) map within an `aggregationKPIs` block, setting the tracking type to a scalar value. The following example sums a metric across entities in the `error` status and averages another metric:
+
[source,yaml]
----
scorecard:
  aggregationKPIs:
    totalCriticalPRs:
      title: "Total Critical PRs"
      description: "Sum of open PRs for entities in error status"
      type: sum
      metricId: github.openPRs
      filter:
        status: error
    avgOpenIssues:
      title: "Average Open Issues"
      description: "Mean open issues count per entity"
      type: average
      metricId: jira.openIssues
----
+
where:
+
`type`:: One of `sum` (total), `average` (mean), `max` (highest value), `min` (lowest value), or `count` (number of entities with a stored value).
`filter.status`:: Optional. Restricts the calculation to entities whose latest threshold evaluation matches the given status key (for example `error`). Only applies to scalar types.

. Optional: Add custom thresholds to classify the aggregated scalar output, using the same rule syntax as metric thresholds:
+
[source,yaml]
----
scorecard:
  aggregationKPIs:
    totalCriticalPRs:
      title: "Total Critical PRs"
      description: "Sum of open PRs for entities in error status"
      type: sum
      metricId: github.openPRs
      filter:
        status: error
      options:
        thresholds:
          rules:
            - key: success
              expression: '<30'
              color: '#6bb300'
            - key: warning
              expression: '30-80'
              color: 'rgb(224, 189, 108)'
            - key: error
              expression: '>80'
              color: '#be1ec7'
----

. In the `app.extensions` section, reference your scalar tracking aggregation ID in the `aggregationId` property of the aggregation card under the `widgetLayout` section of the dynamic home page layout:
+
[source,yaml]
----
app:
  extensions:
    - home-page-layout:homepage/dynamic-homepage-layout:
        config:
          customizable: false
          widgetLayout:
            scorecard-aggregated-card:
              - id: ScorecardTotalCriticalPRs
                props:
                  aggregationId: totalCriticalPRs
                priority: 410
                breakpoints:
                  xl: { w: 4, h: 6, x: 0, y: 0 }
                  lg: { w: 4, h: 6, x: 0, y: 0 }
                  md: { w: 6, h: 6, x: 0, y: 0 }
                  sm: { w: 6, h: 6, x: 0, y: 0 }
                  xs: { w: 12, h: 6, x: 0, y: 0 }
                  xxs: { w: 12, h: 6, x: 0, y: 0 }
----

. Save the modified configuration file and restart your {product} instance.

.Verification
. Access your {product-short} homepage interface.
. Verify that the scalar scorecard summary card displays the calculated value for your chosen tracking type.
