= Understanding the OGX entity provider

include::{docdir}/artifacts/snip-developer-preview-rhoai.adoc[]

[role="_abstract"]
The OGX entity provider ingests AI models and AI agents into the {product} ({product-very-short}) Catalog so that developer teams can discover and consume them alongside other catalog entities.

The OGX entity provider reads from the OGX Model Server, formerly known as LlamaStack, that is provided by {rhoai-brand-name} ({rhoai-short}) 3.5 and later. It performs two tasks:

Ingests AI models::
The provider queries the OGX Model Server for the models that it serves and represents them in the catalog as `AiModelServerAPI` entities. The `AiModelServerAPI` entity kind was introduced in {product-very-short} {product-version} to represent AI model servers and the models that they serve.

Imports AI agents::
The provider reads the OpenAI Agent SDK compatible agents that you define in its configuration and imports them into the catalog as `AiResource` entities with `spec.type: agent`. The `agent` value of `spec.type` extends the existing upstream `AiResource` entity kind, which represents AI skills and rules.

For the full mapping of AI asset categories to entity kinds, and for the annotations that classify each entity, see the AI Asset entity model reference in the {product-very-short} documentation.

[NOTE]
====
The AI Asset entity model and the OpenAI Agent SDK do not require any additional network egress. They are compatible with air-gapped environments. Any network egress that is required to reach an AI model server or agent runtime is specific to the connector or entity provider, and to the endpoints that you configure.
====
