= Populating the API Definition tab in {product-very-short} API entities

[role="_abstract"]
The KServe `InferenceService` resource does not expose the OpenAPI specification of a model server, so the connector cannot populate the *Definition* tab of the generated `AiModelServerAPI` entity automatically. To provide this information, store the OpenAPI specification as a separate {backstage} API entity, import it into the {product-very-short} Catalog, and reference it from the `InferenceService`. The connector then copies the reference into the `spec.apiEntityRef` field of the generated entity, and the *Definition* tab renders the interactive API documentation.

include::{docdir}/artifacts/snip-developer-preview-rhoai.adoc[]

.Prerequisites

* You have installed and configured the {openshift-ai-connector-name-short}.
* You have a running AI model server with an accessible endpoint.
* You have a Git repository that {product-very-short} can read as a catalog location.

.Procedure

. Retrieve the OpenAPI specification from the running endpoint of the model server. Use a tool such as `curl` to fetch the specification from the `/openapi.json` path, and include a `Bearer` token if the model requires authentication:
+
[source,bash]
----
$ curl -k -H "Authorization: Bearer $MODEL_API_KEY" https://$MODEL_ROOT_URL_INCLUDING_PORT/openapi.json | jq > open-api.json
----

. Define an {backstage} API entity that embeds the OpenAPI specification, and store it in a `catalog-info.yaml` file in your Git repository. Set the `spec.definition` field to the contents of the `open-api.json` file:
+
[source,yaml]
----
apiVersion: backstage.io/v1alpha1
kind: API
metadata:
  name: my-model-api
  description: OpenAPI specification for my model server
spec:
  type: openapi
  lifecycle: production
  owner: my-team
  definition: |
    <contents of open-api.json>
----

. Import the `catalog-info.yaml` file into the {product-very-short} Catalog as a location so that the API entity is registered. For more information about registering catalog locations, see the {configuring-book-link}[{configuring-book-title}] guide.

. Annotate the `InferenceService` for the model server with the `rhdh.io/api-entity-ref` annotation, and set its value to the entity reference of the API entity that you registered:
+
[source,yaml]
----
apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: my-model-server
  namespace: my-models
  annotations:
    rhdh.io/api-entity-ref: api:default/my-model-api
spec:
  predictor:
    model:
      modelFormat:
        name: pytorch
----

.Verification

. Restart your {product-very-short} instance, or wait for the connector to run on its configured schedule.
. In the {product-very-short} Catalog, open the generated `AiModelServerAPI` entity for the model server.
. Confirm that the *Definition* tab displays the interactive API documentation from the referenced API entity.
