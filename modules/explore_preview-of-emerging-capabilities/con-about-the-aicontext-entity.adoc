= The AIContext entity for AI content assets

[role="_abstract"]
The `AIContext` entity is a {backstage} Software Catalog entity kind that you can use to register, share, and discover AI content assets in {product} ({product-very-short}).

An AI content asset is a source code repository or an OCI image that contains the skills, rules, and agent definitions that AI coding tools and autonomous agents use. Teams that build agentic coding workflows with tools such as Claude Code, GitHub Copilot, and Cursor often keep these assets in isolated repositories or ad hoc bundles. As a result, other teams cannot discover the assets, which leads to duplicated effort and inconsistent AI behavior across the organization.

When you register an AI content asset as an `AIContext` entity, the asset becomes discoverable in the {product-very-short} Software Catalog alongside Components, APIs, and other entity kinds. Platform Engineers can publish governed, authoritative AI content assets, and developers can find and adopt those assets by using the same search and filtering that they already use for other catalog entities.

== What an AIContext entity registers
An `AIContext` entity registers an asset, not the individual skills, rules, or agents inside it. The unit of registration is the source repository or OCI image that contains the content, which is analogous to how the `Component` entity kind registers a source code repository.

The `AIContext` entity supports two asset location types:

git:: A source code repository that a developer can browse, for example a repository that contains `.claude/agents/`, `.claude/skills/`, or `.cursor/rules/` directories.
oci:: An OCI image reference in a container registry, for example `quay.io/my-org/ai-assets:v1.2.0`. Support for OCI image references is the primary difference from the standard `Component` kind, which does not support OCI locations.

For an OCI image asset, the catalog indexes the image reference only. {product-very-short} does not pull, extract, run, or index the content inside the image, and it does not verify that the reference is reachable when the entity is ingested.

== What an AIContext entity does not do
The initial release of the `AIContext` entity focuses on registering and discovering the asset. It has the following boundaries:

* Individual skills, rules, and agents are files and folders within the asset. They are not registered as separate catalog entities.
* The catalog does not ingest content from OCI images. It records the image reference only.
* Only `git` and `oci` location types are supported. Archive URLs, such as ZIP or TAR files, are not supported.
* The `AIContext` entity is catalog-only. Runtime integration with AI agents that consume the assets is not included.
