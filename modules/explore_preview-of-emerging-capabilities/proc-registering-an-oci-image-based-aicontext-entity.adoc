= Register an OCI image AI content asset

[role="_abstract"]
Register an AI content asset that is packaged as an OCI image by adding a `catalog-info.yaml` file with `kind: AIContext` and a `spec.location` of type `oci`, and then registering it through the standard catalog self-service flow.

.Prerequisites

* You have installed and configured the {product} instance.
* You have published your AI content as an OCI image to a container registry, such as Quay.io.
* You have a repository that you use for catalog configuration, where you can store the `catalog-info.yaml` file.
* If RBAC is enabled, you have a role with the following permissions: `catalog.entity.create`, `catalog.location.create`.

.Procedure

. In your catalog configuration repository, create a file named `catalog-info.yaml`:
+
[source,yaml]
----
apiVersion: backstage.io/v1alpha1
kind: AIContext
metadata:
  name: _<your_ai_content_asset>_
  description: _<asset_brief_description>_
  tags:
    - ai-rules
spec:
  type: mixed
  scope: organization
  owner: _<your_team_name>_
  lifecycle: experimental
  location:
    type: oci
    target: quay.io/_<your_org>_/_<your_asset>_:_<tag>_
----
+
[NOTE]
====
The catalog records the OCI image reference as-is. {product-very-short} does not pull, extract, or run the image content, and it does not verify that the reference is reachable during ingestion.
====
. Commit the `catalog-info.yaml` file to your repository.
. In your {product} navigation menu, go to *Catalog* > *Self-service*.
. On the *Self-service* page, click *Register Existing Component*.
. On the *Register an existing component* page, enter the full URL of the `catalog-info.yaml` file in your repository.
. Complete the wizard instructions.

.Verification

. The asset is listed in the Software Catalog when you filter by *Kind* = *AIContext*.
. On the entity detail page, the asset location is shown as a clickable link to the OCI image reference.
