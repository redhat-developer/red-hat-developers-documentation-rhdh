= Update RBAC policies for {product-very-short} 2.1

[role="_abstract"]
Update your role-based access control (RBAC) policies to the {product} {product-version} feature-linked permission model so that users keep access. Replace each renamed permission identifier and change the action to `use`.

.Prerequisites

* You have completed the platform migration and installed {product-very-short} {product-version}.
* You have access to your RBAC policy files, such as the policy CSV file and any conditional policy files.
* You have reviewed the renamed permissions in xref:ref-permission-changes-from-rhdh-1-10-to-2-1_{context}[Permission changes from {product-very-short} 1.10 to 2.1].

.Procedure

. Locate the old permission identifiers in your RBAC configuration:
.. In your policy CSV file, find every policy line that references a `lightspeed.{asterisk}` permission.
.. In your conditional policy files, find every rule that references a `lightspeed.{asterisk}` permission.
.. In any automation or scripts that generate policies, find every reference to a `lightspeed.{asterisk}` permission.

. Map each old identifier to its {product-very-short} {product-version} equivalent by using xref:ref-permission-changes-from-rhdh-1-10-to-2-1_{context}[Permission changes from {product-very-short} 1.10 to 2.1]. Several old CRUD permissions for a feature map to a single new feature permission.

. Update each policy line to the new permission model:
.. Replace the old permission identifier with the new `intelligent-assistant.{asterisk}` identifier.
.. Change the action to `use`.
.. Remove any duplicate lines that result from several old permissions mapping to the same new permission.

. Re-apply conditional policies:
.. Update each conditional policy rule to reference the new permission identifier and the `use` action.
.. Re-apply the updated conditional policies to your deployment.

. Apply the updated RBAC policies to your {product-very-short} {product-version} deployment.

.Verification

. Sign in as a user whose role grants a migrated permission, and confirm that the user can use the feature and that its UI elements are visible.
. Sign in as a user whose role does not grant a permission, and confirm that the feature and its UI elements are hidden.
. Review the logs and confirm that no policies reference unrecognized `lightspeed.{asterisk}` identifiers.
