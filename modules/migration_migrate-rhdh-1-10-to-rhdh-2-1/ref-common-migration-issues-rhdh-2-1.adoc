= Common migration issues for {product-very-short} 2.1

[role="_abstract"]
After completing all migration steps, some issues, such as silently ignored permissions or missing plugin registrations, might not produce error messages and require targeted verification.

[options="header"]
|===
| Symptom | Cause | Solution

| Custom plugins do not load
| Plugin still uses OFS APIs
| Migrate the plugin to NFS extensions using the xref:proc-migrate-custom-plugins-to-nfs_{context}[custom plugin migration procedure]

| RBAC policies do not work
| Old `lightspeed.{asterisk}` permission names or CRUD action verbs are silently ignored
| Update RBAC policies using the xref:proc-update-rbac-policies-for-rhdh-2-1_{context}[RBAC policy update procedure] and the xref:ref-permission-changes-from-rhdh-1-10-to-2-1_{context}[permission changes reference]

| AI assistant features are unavailable
| Configuration keys still use `lightspeed` instead of `intelligent-assistant`
| Rename configuration keys using the xref:proc-migrate-ai-assistant-configuration_{context}[AI assistant migration procedure]

| Plugins fail to install
| Using a bundled Dynamic Plugin Wrapper local path, such as `./dynamic-plugins/dist/<plugin-name>`, which is no longer shipped in the 2.1 image. npm package references remain valid and supported.
| Replace the local wrapper path with an OCI reference using the xref:proc-migrate-plugins-to-oci-references_{context}[OCI reference migration procedure]

| Container images fail to pull in disconnected environments
| Using old RHEL 9 image names
| Update image references using the xref:ref-container-image-renames-rhel-9-to-rhel-10_{context}[container image renames reference]

|===

// Symptom-cause-solution table for post-migration troubleshooting, informed by test day findings.
