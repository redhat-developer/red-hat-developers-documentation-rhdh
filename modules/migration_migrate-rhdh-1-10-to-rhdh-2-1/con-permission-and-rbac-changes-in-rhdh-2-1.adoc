= Permission and RBAC changes in {product-very-short} 2.1

[role="_abstract"]
{product} {product-version} replaces the CRUD permission model with feature-linked permissions, renames permission identifiers, and unifies actions to `use`. Old identifiers are silently ignored, so update your role-based access control (RBAC) policies before users lose access.

== From CRUD actions to feature-linked permissions

In {product-very-short} 1.x, a feature typically defined several permissions, one for each action, such as `read`, `create`, `update`, and `delete`. A role granted access to each action separately.

In {product-very-short} 2.1, each feature defines a single permission that grants full use of that feature. A role either has the permission to use a feature or it has no access. Because the permissions are no longer split by action, every feature permission uses the `use` action in a role-based access control (RBAC) policy.

This change affects the {ia-short} features, whose permissions were renamed from `lightspeed.{asterisk}` to `intelligent-assistant.{asterisk}` as part of the rebrand.

== Old permission names are silently ignored

{product-very-short} 2.1 does not recognize the old `lightspeed.{asterisk}` permission identifiers or the old CRUD action verbs. A policy that references an old identifier does not produce an error. Instead, the policy has no effect, and the affected users lose access without any warning in the logs.

Because this is a silent failure, you must audit every RBAC policy, conditional policy rule, and automation script that references a renamed permission, and update it to the new identifier and the `use` action.

== UI visibility follows the feature permission

Because each feature maps to a single permission, user interface (UI) visibility for that feature follows the same permission. When a role does not have a feature permission, the corresponding UI elements are hidden for users with that role, rather than shown and then blocked on use. Granting the feature permission restores both the feature and its UI elements.
