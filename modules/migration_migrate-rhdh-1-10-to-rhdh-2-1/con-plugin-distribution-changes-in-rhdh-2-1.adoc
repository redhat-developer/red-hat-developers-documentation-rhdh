= Plugin distribution changes in {product-very-short} 2.1

[role="_abstract"]
In {product-very-short} 2.1, bundled plugin wrappers are removed from the image and plugins are consumed only as Open Container Initiative (OCI) artifacts. A plugin that references a wrapper by a local path no longer resolves after you upgrade.

== Dynamic Plugin Wrappers are removed

In earlier releases, the {product-very-short} image shipped a set of bundled Dynamic Plugin Wrappers that you could reference by using a local path, for example `package: ./dynamic-plugins/dist/<plugin-name>`. {product-very-short} 2.1 no longer ships these wrappers in the image.

As a result, any plugin entry that uses a local wrapper path no longer resolves after the upgrade. This applies to local paths wherever they appear, including the following locations:

* The `dynamic-plugins.yaml` file
* The `global.dynamic.plugins` values in your Helm chart configuration
+
In the 2.1 Helm chart, replace this path with `dynamicPlugins.plugins`.
* Your dynamic plugins ConfigMap referenced in your {backstage} Custom Resource (CR) or the `spec.application.dynamicPlugins` configuration in your CR

[IMPORTANT]
====
The `package: ./dynamic-plugins/dist/<plugin-name>` pattern, and any equivalent local wrapper path, is no longer valid in {product-very-short} 2.1. Plugins that still use these paths fail to load after the upgrade. You must update each entry to an OCI reference before you upgrade. For the required steps, see xref:proc-migrate-plugins-to-oci-references_{context}[Migrate plugin references to OCI format].
====

== Plugins are consumed as OCI artifacts

In {product-very-short} 2.1, you reference a plugin by using one of the following package formats:

`package: oci://<image-reference>`:: References a plugin that is packaged as a pinned OCI image, for example `oci://registry.redhat.io/rhdh/<image-name>:<tag>!<plugin-name>` for a Red Hat supported plugin. Custom or community plugin images can be in your own registry.
`package: ref://<plugin-name>`:: References a catalog plugin by using a stable, name-based reference. {product-very-short} resolves the reference to the corresponding OCI artifact.

The default plugins that ship with {product-very-short} 2.1, and the catalog references that {product-very-short} resolves, are OCI-based.

== The plugin catalog is OCI-only

The plugin catalog, the `Package` entities that it exposes, and the generated plugin tables in the documentation list OCI artifacts only. Bundled wrapper paths are no longer published as valid artifacts and are not available as catalog references.

When you look up a plugin to migrate, use the OCI artifact reference that the plugin catalog or the generated plugin tables provide. Do not expect a local wrapper path to be listed. For the list of supported plugins and their OCI artifact references, see link:{dynamic-plugins-reference-book-link}[{dynamic-plugins-reference-book-title}].

== Legacy plugin wrapper references are discontinued

Bundled Dynamic Plugin Wrapper paths and older community package references are no longer supported in {product-very-short} 2.1. A configuration that installs a plugin from one of these references no longer resolves. Replace these references with the OCI artifact for the equivalent {product-very-short} 2.1 plugin. For a mapping of discontinued references to their {product-very-short} 2.1 OCI references, see xref:ref-plugin-wrapper-to-oci-mapping_{context}[Plugin wrapper to {product-very-short} 2.1 OCI reference mapping].

[NOTE]
====
This change is a removed function in {product-very-short} 2.1: the {product-very-short} image no longer ships bundled plugin wrappers, and the default plugins and catalog references are OCI-based. For the complete list of removed functions, see the {product-very-short} 2.1 release notes.
====
