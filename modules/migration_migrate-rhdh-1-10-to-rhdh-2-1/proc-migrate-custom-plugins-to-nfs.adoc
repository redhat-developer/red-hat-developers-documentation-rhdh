= Migrate custom plugins to the New Frontend System

[role="_abstract"]
Custom plugins built with Old Frontend System (OFS) APIs must support the New Frontend System (NFS) before you deploy them on {product} 2.1. You do not rewrite the plugins: you add an NFS entry point and extensions alongside your existing code, move YAML wiring into them, and re-export the plugin.

.Prerequisites

* You have access to the source code of your custom plugins.
* You have an NFS-enabled {product} instance for testing. {product} 2.1 ships the New Frontend System by default, so use a {product} 2.1 instance or {product} Local (`rhdh-local`) configured for 2.1. Testing only against an Old Frontend System instance does not verify that the NFS entry point works.

.Procedure

. Add an NFS entry point to each custom plugin:
.. Create a `src/alpha.tsx` file that defines the plugin with `createFrontendPlugin` and the NFS extension blueprints, such as `PageBlueprint`, `EntityCardBlueprint`, `EntityContentBlueprint`, and `ApiBlueprint`.
.. Export the `./alpha` entry point from `package.json`.
.. Keep the entry point lightweight by loading page and card UI with `import()` instead of static imports.
+
You can keep the existing `PluginRoot` export so the plugin continues to work with the Old Frontend System during the transition.

. Move your frontend wiring from YAML into plugin extensions. For each item in your `dynamicPlugins.frontend` configuration, implement the equivalent NFS extension in `src/alpha.tsx`:
+
--
* Replace `dynamicRoutes` and `menuItem` entries with `PageBlueprint` extensions.
* Replace `mountPoints` and `entityTabs` entries with `EntityCardBlueprint`, `EntityContentBlueprint`, or `HomePageWidgetBlueprint` extensions.
* Replace `routeBindings` with route references bound through `app.routes.bindings`.
* Replace `appIcons` with page extension icons.
* Replace `apiFactories` with `ApiBlueprint` extensions.
--
+
For the complete key-by-key mapping, see xref:ref-ofs-to-nfs-config-key-mapping_{context}[Old Frontend System to New Frontend System configuration key mapping].

. Re-export your plugin as a dynamic plugin by using the {product} CLI.

. Test your updated plugin on an NFS-enabled instance. Add the plugin to a {product} 2.1 instance or to {product} Local configured for 2.1, set `app.packages: all` (or include your package explicitly), and verify routes, entity tabs, cards, APIs, and cross-plugin links.

.Verification

* Confirm that the plugin loads without errors on the NFS-enabled instance and that all functionality works as expected.
