= Pre-upgrade checklist

[role="_abstract"]
Before migrating to {product} 2.1, audit your current deployment to identify what needs to be updated.

[options="header"]
|===
| Item | Action | Notes

| Database backup
| Create a backup of your {product} database
| Essential for rollback if migration fails

| Custom plugins inventory
| List all custom plugins using OFS APIs
| Custom plugins require migration to NFS

| Helm values export
| Export current Helm chart values using `helm get values`
| Required for translating configuration keys

| RBAC permissions audit
| Audit all RBAC policies, conditional policy rules, and automation scripts for renamed or removed permissions
| Permission identifiers are renamed and CRUD actions are unified to `use`. See xref:ref-permission-changes-from-rhdh-1-10-to-2-1_{context}[Permission changes from {product-very-short} 1.10 to 2.1].

| Container image list
| Identify mirrored RHEL 9 images for disconnected environments
| Image names change from RHEL 9 to RHEL 10

| Network connectivity audit
| List the network connections your deployment relies on, such as external APIs, custom sidecars, and cross-namespace services
| Both the 2.1 Helm chart and the 2.1 Operator deploy default-deny NetworkPolicies and allow only known traffic (DNS, PostgreSQL, the Kubernetes API server, and OpenShift ingress and monitoring). You must add NetworkPolicy rules for any additional connections after the upgrade, or they are silently blocked. For the deployed policies, see the link:https://github.com/redhat-developer/rhdh-chart/blob/release-2.1/charts/rhdh/templates/network-policies.yaml[`network-policies.yaml` template] in the `rhdh-chart` repository.

| Cluster version
| Confirm the cluster runs {ocp-brand-name} {ocp-version-min} or later, or Kubernetes {kubernetes-version} or later
| {product-very-short} {product-version} requires these minimum versions

|===
