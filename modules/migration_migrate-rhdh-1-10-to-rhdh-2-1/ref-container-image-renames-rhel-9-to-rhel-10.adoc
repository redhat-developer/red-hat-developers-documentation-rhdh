= Container image renames from RHEL 9 to RHEL 10

[role="_abstract"]
The {product} 2.1 container images that Red Hat builds are based on RHEL 10 instead of RHEL 9. This reference lists the image name changes for these {product} containers, including images for disconnected environment mirroring.

[NOTE]
====
Not all images that {product} deploys are based on RHEL 10. Some images that Red Hat does not build directly but still deploys as part of {product} remain on RHEL 9, for example:

* `registry.redhat.io/lightspeed-core/lightspeed-stack-rhel9`: Deployed as a sidecar by default because the {ia-brand-name} is enabled by default in {product} 2.1.
* `registry.redhat.io/offline-knowledge-portal/rhokp-rhel9`: Deployed when you enable the Offline Knowledge Portal (OKP) feature for the {ia-brand-name}.

If you mirror images for a disconnected environment, include these RHEL 9 images in your mirroring configuration when the corresponding features are enabled.
====

[options="header"]
|===
| RHEL 9 Image Name (1.x) | RHEL 10 Image Name (2.1) | Notes

| `registry.redhat.io/rhdh/rhdh-rhel9`
| `registry.redhat.io/rhdh/rhdh-rhel10`
| Main {product} image

| `registry.redhat.io/rhdh/rhdh-postgresql-rhel9`
| `registry.redhat.io/rhdh/rhdh-postgresql-rhel10`
| PostgreSQL image

| `registry.redhat.io/rhdh/rhdh-rhel9-operator`
| `registry.redhat.io/rhdh/rhdh-rhel10-operator`
| Operator image

| `registry.redhat.io/rhdh/rhdh-must-gather-rhel9`
| `registry.redhat.io/rhdh/rhdh-must-gather-rhel10`
| `must-gather` image for collecting diagnostic data

| `registry.redhat.io/rhdh/rhdh-rag-content-rhel9`
| _(removed in 2.1)_
| The RAG content image is removed in 2.1. Remove any references to it from your mirroring configuration.

|===

[IMPORTANT]
====
The 2.1 chart ships every container image with an explicit digest by default. When both a `tag` and a `digest` are set, the chart renders the image reference as `tag@digest`. If you override an image `tag` while the chart's default `digest` still points to the original image, the reference can fail to resolve at pull time because Helm merges the default digest into your values.

When you override an image with a custom tag, either set `digest: ""` to clear the default digest, or set `digest` to the correct digest for your tag. This applies to every image block, including `image`, `catalogIndex.image`, `intelligentAssistant.core.image`, and `postgresql.image`.
====

[NOTE]
====
If you mirror images for a disconnected environment, update your mirroring scripts to the RHEL 10 image set. Scripts that reference the RHEL 9 image names do not work with 2.1.
====
