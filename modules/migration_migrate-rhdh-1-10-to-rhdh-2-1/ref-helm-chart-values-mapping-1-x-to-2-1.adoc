= Helm chart values mapping from 1.x to 2.1

[role="_abstract"]
The {product-very-short} 2.1 Helm chart no longer wraps the upstream `backstage` subchart. Values that lived under the `upstream.backstage` and `global` paths are flattened to root-level keys, so you cannot reuse your 1.x values file. Use this reference to translate each value.

[NOTE]
====
Fields that are not listed in the following tables keep the same path. Where a table shows a new path, use that path. If a field you use is not mentioned at all, carry it over as-is.

This mapping is based on the upstream chart maintainers' link:https://github.com/redhat-developer/rhdh-chart/blob/release-2.1/charts/rhdh/docs/migration-from-backstage-chart.md[upstream Helm chart migration guide], which you can consult for additional detail.
====

== Default changes to review before upgrading

Before you translate your values, check these default changes:

* *Intelligent Assistant* (formerly Lightspeed) remains enabled by default. If you explicitly disabled it in your 1.x chart, set `intelligentAssistant.enabled: false`.
* *PostgreSQL image* defaults to `registry.redhat.io/rhel10/postgresql-18`, but PostgreSQL 15 remains supported on Helm. An existing PostgreSQL 15 data directory does not start on PostgreSQL 18, so you must choose one of the following paths:
+
--
** To upgrade the database to PostgreSQL 18, see xref:proc-upgrade-local-postgresql-15-to-18-helm_{context}[Upgrade the local PostgreSQL database for Helm deployments].
** To keep PostgreSQL 15, set `postgresql.image.repository: rhel9/postgresql-15` (the 1.10 image; `rhel10/postgresql-15` does not exist). Because the default `postgresql.image.digest` reflects the PostgreSQL 18 image, you must also set `postgresql.image.digest` to the digest of the 1.10 PostgreSQL 15 image. Read that digest from the running database StatefulSet before you upgrade:
+
[source,terminal]
----
$ oc -n <your_namespace> get statefulset <release_name>-postgresql -o jsonpath='{.spec.template.spec.containers[0].image}'
----
+
If you already upgraded with the PostgreSQL 18 default and the database is crash-looping, updating the values is not enough on its own: delete the stuck `<release_name>-postgresql-0` pod so that the StatefulSet recreates it with the PostgreSQL 15 image.
--
* *Autoscaling* (`autoscaling.maxReplicas`) default changed from `100` to `3`.

== Key structural changes

[options="header"]
|===
| Aspect | 1.x chart | 2.1 chart

| Template ownership
| Delegates to the upstream {backstage} subchart
| Owns all templates directly

| System volumes, mounts, and env vars
| You listed them in full under `upstream.backstage.extraVolumes`, `extraVolumeMounts`, and `extraEnvVars`
| Hard-coded in templates; the `extra{asterisk}` keys only add your custom values

| Init containers
| You specified the full init container array
| System init containers are managed by the chart; use `preInitContainers` and `extraInitContainers` to add custom ones

| Lightspeed
| `global.lightspeed.{asterisk}`
| Rebranded to `intelligentAssistant.{asterisk}`

| OpenShift Route
| `route.{asterisk}`
| `openshift.route.{asterisk}`
|===
