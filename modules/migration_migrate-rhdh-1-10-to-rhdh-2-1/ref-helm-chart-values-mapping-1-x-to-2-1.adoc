= Helm chart values mapping from 1.x to 2.1

[role="_abstract"]
The {product-very-short} 2.1 `redhat-developer-hub` chart is a clean break from the 1.x `backstage` chart. Values that lived under `upstream.backstage` and `global` paths are flattened to root-level keys, so you cannot reuse your 1.x values file. Use this reference to translate each value.

[NOTE]
====
Fields that are not listed in the following tables keep the same path. Where a table shows a new path, use that path. If a field you use is not mentioned at all, carry it over as-is.

This mapping is based on the upstream chart maintainers' link:https://github.com/redhat-developer/rhdh-chart/blob/release-2.1/charts/rhdh/docs/migration-from-backstage-chart.md[Migration guide: `backstage` chart to `redhat-developer-hub` chart], which you can consult for additional detail.
====

== Default changes to review before upgrading

Before you translate your values, check these default changes:

* *Intelligent Assistant* (formerly Lightspeed) remains enabled by default. If you explicitly disabled it in your 1.x chart, set `intelligentAssistant.enabled: false`.
* *PostgreSQL image* defaults to `registry.redhat.io/rhel10/postgresql-18`, but PostgreSQL 15 remains supported. For an existing PostgreSQL 15 data directory, either upgrade the database during this migration or set `postgresql.image.repository: rhel10/postgresql-15` to keep PostgreSQL 15.
* *Autoscaling* (`autoscaling.maxReplicas`) default changed from `100` to `3`.

== Key structural changes

[options="header"]
|===
| Aspect | 1.x chart | 2.1 chart

| Template ownership
| Delegates to the upstream Backstage subchart
| Owns all templates directly

| System volumes, mounts, and env vars
| You listed them in full under `upstream.backstage.extraVolumes`, `extraVolumeMounts`, and `extraEnvVars`
| Hardcoded in templates; the `extra{asterisk}` keys only add your custom values

| Init containers
| You specified the full init container array
| System init containers are managed by the chart; use `preInitContainers` and `extraInitContainers` to add custom ones

| Lightspeed
| `global.lightspeed.{asterisk}`
| Rebranded to `intelligentAssistant.{asterisk}`

| OpenShift Route
| `route.{asterisk}`
| `openshift.route.{asterisk}`
|===

[NOTE]
====
The 1.x chart used flat `lightspeed.{asterisk}` paths and some settings are restructured rather than simply renamed. When migrating AI assistant configuration, map Helm values to `intelligentAssistant.{asterisk}` as shown in this table. The app-config renames from `lightspeed` to `intelligent-assistant` are a separate step. See xref:proc-migrate-ai-assistant-configuration_{context}[Migrate AI assistant configuration].
====
