= Test custom plugins locally before upgrading

[role="_abstract"]
Validate custom plugin migrations locally using the +rhdh-local+ project before deploying to staging or production. Local testing catches extension resolution errors, missing dependencies, and configuration issues early in the migration process.

.Prerequisites

* You have Node.js 18 or later installed
* You have yarn 1.x installed
* You have migrated your custom plugin to include an +/alpha+ export with extension blueprints
* You have exported your plugin as a dynamic plugin using +npx @red-hat-developer-hub/cli plugin export+

.Procedure

. Clone the +rhdh-local+ project:
+
[source,terminal]
----
$ git clone https://github.com/redhat-developer/rhdh.git
$ cd rhdh
----

. Check out the {product} 2.1 release branch:
+
[source,terminal]
----
$ git checkout release-2.1
----
+
The +release-2.1+ branch includes development builds that match the {product} 2.1 platform behavior.

. Install dependencies:
+
[source,terminal]
----
$ yarn install
----

. Copy your exported plugin to the +rhdh-local+ dynamic plugins directory:
+
[source,terminal]
----
$ cp -r /path/to/your/plugin/dist-dynamic rhdh-local/dynamic-plugins/my-plugin
----
+
The +dist-dynamic+ directory contains the plugin export generated by the {product-very-short} CLI.

. Configure the plugin in +rhdh-local/app-config.local.yaml+:
+
[source,yaml]
----
dynamicPlugins:
  plugins:
    - package: file:./dynamic-plugins/my-plugin
      disabled: false
----
+
For custom plugins published as OCI images, use the image reference instead:
+
[source,yaml]
----
dynamicPlugins:
  plugins:
    - package: quay.io/my-org/my-plugin:2.1
      disabled: false
----

. (Optional) Add extension overrides to test configuration behavior:
+
[source,yaml]
----
app:
  extensions:
    - entity-card:my-plugin/my-component:
        config:
          filter: kind:Component
----

. Start the local {product-very-short} instance:
+
[source,terminal]
----
$ yarn dev
----
+
The development server runs at +http://localhost:3000+.

. Monitor the console output for plugin loading messages:
+
--
Successful plugin load::
+
[source,terminal]
----
[INFO] Loading dynamic plugin: my-plugin
[INFO] Loaded 3 extensions from my-plugin/alpha
----

Missing manifest error::
+
[source,terminal]
----
[ERROR] Could not find manifest for frontend plugin my-plugin
----
+
This indicates the plugin was not exported correctly or the +plugin-manifest.yaml+ file is missing.

Missing +/alpha+ export warning::
+
[source,terminal]
----
[WARN] Skipping dynamic plugin remote module 'my-plugin' since it doesn't export a new 'FrontendFeature' as default export
----
+
This indicates the plugin's +package.json+ does not include the +./alpha+ export or the alpha export does not use +createFrontendPlugin+.
--

. Open the {product-very-short} UI at +http://localhost:3000+ and verify plugin functionality:
+
* Navigate to an entity page where your plugin should appear
* Verify that custom cards, tabs, or pages render correctly
* Check that conditional rendering (entity kind filters) works as expected
* Test any plugin-specific features or interactions

. Open the browser developer console and check for errors:
+
--
Extension resolution errors::
Look for messages about unresolved extensions or missing dependencies. These indicate blueprint configuration issues.

Plugin loading failures::
Check the Network tab for failed plugin module loads. These indicate packaging or export issues.

Runtime errors::
Verify that no JavaScript errors occur when interacting with plugin features.
--

.Verification

* The plugin appears in the +/admin+ plugins list with status "Loaded"
* All plugin features render in the expected locations
* No console errors or warnings related to the plugin
* Backend logs show successful plugin initialization

.Troubleshooting

Plugin does not load::
Verify that the +plugin-manifest.yaml+ file exists in the +dist-dynamic+ output and includes the +/alpha+ export entry. Check that the plugin +package.json+ has the +exports+ field correctly configured.

Extension does not appear::
Check the browser console for extension resolution errors. Verify that extension IDs in +app.extensions+ overrides match the IDs declared in the plugin's +createFrontendPlugin+ call.

Conditional rendering fails::
Review the +filter+ configuration in the extension blueprint. Entity filters use the format +kind:Component+ or +type:service+. Complex filters require TypeScript functions in the blueprint code.

Import errors::
Verify that all blueprint dependencies (+@backstage/frontend-plugin-api+, +@backstage/plugin-catalog-react+) are listed in the plugin's +package.json+ dependencies.
