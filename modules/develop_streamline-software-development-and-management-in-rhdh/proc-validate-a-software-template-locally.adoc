= Validate a software template locally

[role="_abstract"]
To catch template errors before they reach a running instance, validate locally with no {product} connection required. The `validate` command runs YAML schema, gotcha, and optional Nunjucks checks so you can fix issues early and avoid failed catalog imports.

.Prerequisites

* You installed the `rhdh-templates` skill and authored a template.
* Optional: `djlint` is installed for Nunjucks linting of skeleton files.

.Procedure

. Run local validation against your template directory:
+
[source,terminal]
----
python <skill_dir>/scripts/validate.py --path <template_dir> --repo --json
----
+
The `--repo` flag also checks the root `location.yaml`.

. To lint Nunjucks in skeleton files, add the `--lint-skeleton` flag:
+
[source,terminal]
----
python <skill_dir>/scripts/validate.py --path <template_dir> --lint-skeleton --json
----

. Auto-fix common issues, such as missing `{% raw %}` blocks or wrong action ID casing:
+
[source,terminal]
----
python <skill_dir>/scripts/fix_gotchas.py --path <template_dir>/template.yaml --apply
----

. Address any remaining findings manually, then re-run validation.

.Verification

. Validation reports `ok: true` with a critical count of `0`. Critical findings, such as a wrong `apiVersion` or invalid action casing, cause failures in the Template Editor.
. You reviewed all warnings and decided whether to fix them before merging.
