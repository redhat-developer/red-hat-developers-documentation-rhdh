= Troubleshoot workflow runs in Orchestrator

[role="_abstract"]
Use the workflow run details and runs list to identify who started a run, narrow the list of runs, and locate a failed workflow step.

.Prerequisites

* You have access to an {ocp-short} deployment where the Orchestrator plugin is enabled.

.Procedure

. Open the Orchestrator workflows view and select the workflow that you want to investigate.
. In the workflow runs list, review the *Triggered by* column to identify the user who started each run.
. Use the available filters to narrow the list:
+
.. Enter a username in the *Triggered by* filter to display runs started by that user.
.. Enter a workflow name in the workflow name filter to display matching runs.
+
. Select a run to open its details page.
. Review the *Triggered by* field on the run details page to confirm the triggering user.
. Review the workflow visualization to understand the run status:
+
.. Completed steps are shown as completed.
.. The active step is shown as in progress.
.. A failed step is shown as failed, along with the completed steps before it.
+
The visualization is read-only. It shows the workflow definition and the latest status reported for the run; it does not start, stop, retry, skip, or otherwise modify workflow steps.
. Refresh the run details page to retrieve the latest status when the run is still in progress.

[NOTE]
====
The information shown in the Orchestrator UI is subject to your permissions. You can view only workflows and runs that you are authorized to access.
====
