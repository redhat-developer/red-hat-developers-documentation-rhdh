= Troubleshoot workflow runs in Orchestrator

[role="_abstract"]
To identify execution issues, filter workflow runs, and locate a failed workflow step, review the workflow run details in Orchestrator.

.Prerequisites

* You have access to an {ocp-short} deployment where the Orchestrator plugin is enabled.
* Your account has role-based permissions to view target workflows and runs.

.Procedure

. Open the Orchestrator workflows view and select the workflow that you want to investigate.
. In the workflow runs list, review the following columns:
+
.. Review the *Run by* column to identify the user who started each run.
.. Review the *Entity* column to identify the catalog entity that is associated with each run.
. Use the sidebar filters to narrow the list:
+
.. Select a user in the *Run by* filter to display runs started by that user. The *Run by* filter is available only to users with the instance admin permission (`orchestrator.instanceAdminView`).
.. Select an entity in the *Entity* filter to display runs that are associated with a specific catalog entity.
.. Enter a workflow name in the workflow name filter to display matching runs.
. Select a run to open its details page.
. Review the *Run by* field in the instance details to confirm the user who started the run.
. In the *Progress* card, review the workflow graph to understand the run status:
+
.. Completed steps are shown as completed.
.. The active step is shown as in progress.
.. A failed step is shown as failed, along with the completed steps before it.
+
The workflow graph is read-only. It shows the workflow definition and the latest status reported for the run; it does not start, stop, retry, skip, or otherwise modify workflow steps.
+
The *Results* card is a separate card on the same page and shows the workflow output only; it does not contain the workflow graph.
. Refresh the run details page to retrieve the latest status when the run is still in progress.
+
[NOTE]
====
The information shown in the Orchestrator UI is subject to your permissions. You can view only workflows and runs that you are authorized to access.
====

.Verification

* Verify that the workflow graph identifies the specific step status and details.
