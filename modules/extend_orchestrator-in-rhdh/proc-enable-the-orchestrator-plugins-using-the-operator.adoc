= Enable the Orchestrator plugins using the Operator

[role="_abstract"]
You can enable the Orchestrator plugins in {product-very-short} by configuring dynamic plugins in your {product-custom-resource-type} custom resource (CR).

.Prerequisites
* You have installed {product-very-short} on {ocp-short}.
* You have the `edit` or `admin` role in the namespace, or have been granted RBAC permissions to create and update ConfigMaps (`kubectl create configmap`, `kubectl apply -f`).

.Procedure

. To enable the Orchestrator plugins with default settings, set `enabled: true` for the corresponding packages.
+
The `{{inherit}}` attribute resolves to the default plugin version *and default configuration* for your version of {product-short}.
Configuration specified in `pluginConfig` will override these defaults.
+
[source,yaml,subs="+attributes,+quotes"]
----
- package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-orchestrator:{{inherit}}"
  enabled: true
- package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-orchestrator-backend:{{inherit}}"
  enabled: true
  dependencies:
    - ref: sonataflow
- package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-scaffolder-backend-module-orchestrator:{{inherit}}"
  enabled: true
- package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-orchestrator-form-widgets:{{inherit}}"
  enabled: true
----
+
[NOTE]
====
If you need a specific plugin version, replace `{{inherit}}` with the version tag, such as `1.3.0`.
When you use the Operator, the `ref: sonataflow` field installs the OpenShift Serverless and OpenShift Serverless Logic resources.
====
+
The following example shows a complete configuration of the Orchestrator plugin `dynamic-plugins` config map:
+
[source,yaml,subs="+attributes,+quotes"]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: orchestrator-plugin
data:
    dynamic-plugins.yaml: |
      includes:
        - dynamic-plugins.default.yaml
      plugins:
        - package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-orchestrator:{{inherit}}"
          enabled: true
        - package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-orchestrator-backend:{{inherit}}"
          enabled: true
          dependencies:
            - ref: sonataflow
        - package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-scaffolder-backend-module-orchestrator:{{inherit}}"
          enabled: true
        - package: "oci://registry.access.redhat.com/rhdh/red-hat-developer-hub-backstage-plugin-orchestrator-form-widgets:{{inherit}}"
          enabled: true
----

. (Optional) Configure backend authentication to allow Orchestrator components to communicate with the {product-very-short} API.
+
This step is required only when your workflow definitions include API calls to {product-very-short} plugins, such as the notifications or scaffolding plugins.
+
[source,yaml,subs="attributes+"]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config-rhdh
data:
  {my-app-config-file}: |-
    backend:
      auth:
        externalAccess:
          - type: static
            options:
              token: ${BACKEND_SECRET}
              subject: orchestrator
---
apiVersion: v1
kind: Secret
metadata:
  name: backend-auth-secret
stringData:
  # Run the following command to generate a secure random value:
  # node -p 'require("crypto").randomBytes(24).toString("base64")'
  BACKEND_SECRET: "<GENERATED_VALUE>"
----
+
[IMPORTANT]
====
Replace `<GENERATED_VALUE>` with a securely generated random token. Do not use example or placeholder values in production environments.
====

. If you have configured backend authentication in the previous step, update your {product-custom-resource-type} CR to reference the secret:
+
[source,yaml,subs="+attributes,+quotes"]
----
apiVersion: rhdh.redhat.com/v1alpha5
kind: {product-custom-resource-type}
metadata:
  name: orchestrator
spec:
  application:
    appConfig:
      configMaps:
        - name: app-config-rhdh
    dynamicPluginsConfigMapName: orchestrator-plugin
    extraEnvs:
      secrets:
        - name: backend-auth-secret
----
+
[NOTE]
====
If plugins fail to load, check that the ConfigMap name matches exactly (case-sensitive) and that the ConfigMap exists in the same namespace: `oc get configmap orchestrator-plugin -n <namespace>`.
====

.Verification
. Navigate to the {product-short} console.
. In the left sidebar, verify that the *Orchestrator* menu item appears.
. Click *Orchestrator* and confirm that the workflow list page loads without errors.
. Check the pod logs to confirm all Orchestrator plugins loaded successfully:
+
[source,shell]
----
oc logs -n <namespace> deployment/<rhdh-deployment-name> -c backstage | grep orchestrator
----
