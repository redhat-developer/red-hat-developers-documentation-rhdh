= Configure Azure Managed Identity for PostgreSQL by using the Operator

[role="_abstract"]
Configure passwordless authentication to Azure Database for PostgreSQL by using Microsoft Entra ID with the {product} Operator.

.Prerequisites

* You have an Azure Database for PostgreSQL Flexible Server instance with Microsoft Entra ID authentication enabled.
* You have created a managed identity (system-assigned or user-assigned) or a Microsoft Entra ID service principal, and granted it login access to your PostgreSQL instance. For more information, refer to the link:https://learn.microsoft.com/en-us/azure/postgresql/flexible-server/how-to-configure-sign-in-azure-ad-authentication[Microsoft Azure documentation].
* You have configured Azure Workload Identity to federate the managed identity with the Kubernetes service account used by the {product-very-short} pod. For more information, refer to the link:https://learn.microsoft.com/en-us/azure/aks/workload-identity-overview[Azure Workload Identity documentation].
* You meet the {about-book-link}#rhdh-sizing_about-rhdh[Sizing requirements for external PostgreSQL deployments].
* You have installed the {product} Operator.

.Procedure

. Create a credential secret to connect to the PostgreSQL instance:
+
[source,terminal,subs="+attributes,+quotes"]
----
$ cat <<EOF | oc -n {my-product-namespace} create -f -
apiVersion: v1
kind: Secret
metadata:
  name: {my-product-database-secrets}
type: Opaque
stringData:
  POSTGRES_HOST: <db_host>
  POSTGRES_PORT: "<db_port>"
  POSTGRES_USER: <entra_user>
EOF
----
+
Where:
+
`{my-product-database-secrets}`:: The credential secret name.
`<db_host>`:: Your Azure Database for PostgreSQL Flexible Server host name.
`<db_port>`:: Your PostgreSQL instance port number, such as `5432`.
`<entra_user>`:: The Entra ID user name for database authentication. This is the name of the managed identity, service principal, or Entra ID user that you granted login access to the database.
+
[NOTE]
====
Unlike password-based authentication, this secret does not include `POSTGRES_PASSWORD`. The password is replaced by a short-lived token that {product-very-short} obtains automatically from Entra ID.
====

. Create a config map to configure the database connection with Entra ID authentication:
+
[source,terminal,subs="+attributes,+quotes"]
----
$ cat <<EOF | oc -n {my-product-namespace} create -f -
apiVersion: v1
kind: ConfigMap
metadata:
  name: {my-app-config-config-map}
data:
  app-config-database.yaml: |
    backend:
      database:
        connection:
          type: azure
          host: \${POSTGRES_HOST}
          port: \${POSTGRES_PORT}
          user: \${POSTGRES_USER}
EOF
----

. Create your `{product-custom-resource-type}` custom resource (CR):
+
[source,terminal,subs="+attributes,+quotes"]
----
cat <<EOF | oc -n {my-product-namespace} create -f -
apiVersion: rhdh.redhat.com/v1alpha5
kind: {product-custom-resource-type}
metadata:
  name: <backstage_instance_name>
spec:
  database:
    enableLocalDb: false
  deployment:
    patch:
      spec:
        template:
          metadata:
            labels:
              azure.workload.identity/use: "true" # <1>
          spec:
            serviceAccountName: <service_account_name> # <2>
  application:
    appConfig:
      configMaps:
        - name: {my-app-config-config-map}
    extraEnvs:
      secrets:
        - name: {my-product-database-secrets}
    # ...
EOF
----
+
<1> Required for Azure Workload Identity to inject the token credentials into the pod.
<2> The Kubernetes service account federated with your Azure managed identity.
+
Where:
+
`spec.database.enableLocalDb`:: Set to `false` to disable creating local PostgreSQL instances.
`spec.deployment.patch`:: Patches the pod template to add the Azure Workload Identity label and service account. For more information, see xref:configure-rhdh-deployment-when-using-the-operator_configuring-rhdh[Patch deployment resources to customize Operator pod specifications].
`spec.application.appConfig.configMaps`:: The config map containing the `connection.type: azure` database configuration.
`{my-product-database-secrets}`:: The credential secret name.
`<service_account_name>`:: The name of the Kubernetes service account federated with your Azure managed identity.

. Optional: To use a user-assigned managed identity, add `clientId` to the `tokenCredential` block in your config map:
+
[source,yaml,subs="+quotes"]
----
backend:
  database:
    connection:
      type: azure
      host: ${POSTGRES_HOST}
      port: ${POSTGRES_PORT}
      user: ${POSTGRES_USER}
      tokenCredential:
        clientId: <azure_client_id>
----

. Apply the `{product-custom-resource-type}` CR to the namespace where you have deployed the {product-short} instance.

.Verification

* Check the {product-very-short} pod logs for successful database connections:
+
[source,terminal]
----
$ oc logs -n <your_namespace> deployment/<backstage_instance_name>-backstage -c backstage | grep -i "database"
----
+
If the connection is successful, you should not see any password-related errors or authentication failures.
