= Dynamic plugins configuration file

[role="_abstract"]
The `dynamic-plugins.yaml` file controls which dynamic plugins are enabled in your {product-short} instance. It defines a list of plugins to install, disable, or configure.

The file contains the following two main sections:

`includes`::
References a base configuration file (`dynamic-plugins.default.yaml`) that is included with {product-short}. This file contains the default plugin configuration.

`plugins`::
A list of plugin entries that override or extend the base configuration. Each entry specifies a `package` (the plugin path), an `enabled` field (boolean) to activate or deactivate the plugin, and an optional `pluginConfig` section with plugin-specific YAML that the application configuration merges in. The `enabled` field aligns with upstream {backstage} conventions and offers more intuitive positive logic. For backward compatibility, the existing `disabled` field is also supported; when both fields are present, `enabled` takes precedence.

You can provision the `dynamic-plugins.yaml` file in different ways depending on your deployment method:

With the Operator:: Create a config map containing the `dynamic-plugins.yaml` data and reference it in the `{product-custom-resource-type}` custom resource by using `spec.application.dynamicPluginsConfigMapName`.

With the Helm chart:: Configure plugins inline by using the `global.dynamic.plugins` Helm values.
