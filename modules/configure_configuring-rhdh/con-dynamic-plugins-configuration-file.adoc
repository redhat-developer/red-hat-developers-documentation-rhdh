= Dynamic plugins configuration file

[role="_abstract"]
The `dynamic-plugins.yaml` file controls which dynamic plugins are enabled in your {product-short} instance.
It defines a list of plugins to install, disable, or configure.

The file contains the following two main sections:

`includes`::
References a base configuration file (`dynamic-plugins.default.yaml`) that is included with {product-short}. This file contains the default plugin configuration.

`plugins`::
A list of plugin entries that override or extend the base configuration. Each entry specifies a `package` (the plugin path), a `disabled` field (boolean), and an optional `pluginConfig` section with plugin-specific YAML that is merged into the application configuration.

You can provision the `dynamic-plugins.yaml` file in different ways depending on your deployment method:

With the Operator:: Create a config map containing the `dynamic-plugins.yaml` data and reference it in the `{product-custom-resource-type}` custom resource using `spec.application.dynamicPluginsConfigMapName`, or configure plugins inline using `spec.application.dynamicPlugins`.

With the Helm chart:: Configure plugins inline by using the `global.dynamic.plugins` Helm values.

When you use the Operator, you can configure dynamic plugins in two mutually exclusive ways:

* *Inline configuration*: Define plugins directly in the `spec.application.dynamicPlugins` field of the `{product-custom-resource-type}` custom resource.
This method is available in {product-short} {product-version-next} and later.
Use inline configuration for straightforward deployments where you do not need to share plugin configuration across multiple instances.
* *ConfigMap-based configuration*: Store the `dynamic-plugins.yaml` file in a separate `ConfigMap` and reference it using `spec.application.dynamicPluginsConfigMapName`.
Use ConfigMap-based configuration for complex deployments requiring configuration reuse or environment-specific variations.
