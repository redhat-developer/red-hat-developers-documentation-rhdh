= Azure Managed Identity for PostgreSQL connections

[role="_abstract"]
You can configure {product} to authenticate to Azure Database for PostgreSQL by using Microsoft Entra ID instead of a static password. {product-very-short} obtains short-lived OAuth access tokens from Entra ID and uses them as the PostgreSQL password, eliminating stored database credentials.

This passwordless authentication requires setting `backend.database.connection.type` to `azure` in your application configuration and removing the `password` field. {product-very-short} automatically renews tokens before they expire.

The following table describes the credential type that {product-very-short} uses based on the `tokenCredential` fields provided in the configuration:

[cols="1,1", options="header"]
|===
| Configuration fields provided
| Credential type used

| `tenantId`, `clientId`, and `clientSecret`
| `ClientSecretCredential` (service principal)

| `clientId` only
| `ManagedIdentityCredential` (user-assigned managed identity)

| None
| `DefaultAzureCredential` (system-assigned managed identity, environment variables, or Azure CLI)
|===

The recommended approach for production deployments on {aks-brand-name} ({aks-short}) or Azure Red Hat OpenShift (ARO) is to use a managed identity with Azure Workload Identity, which maps a Kubernetes service account to an Azure managed identity without requiring any secrets.

[NOTE]
====
The RBAC plugin uses a separate database connection for storing Casbin policies. When you configure `connection.type: azure`, the RBAC plugin automatically uses the same token-based authentication. No additional RBAC-specific database configuration is required.
====

[IMPORTANT]
====
Each {product-very-short} pod creates its own database connection pool, and the RBAC plugin creates an additional connection pool. If you run multiple replicas in a high-availability configuration, size your Azure Database for PostgreSQL tier to accommodate the total number of connections. Consider lowering `backend.database.knexConfig.pool.max` to reduce the per-plugin pool size.
====
