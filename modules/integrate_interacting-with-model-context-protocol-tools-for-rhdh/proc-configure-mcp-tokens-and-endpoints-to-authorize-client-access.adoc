= Configure MCP tokens and endpoints to authorize client access

[role="_abstract"]
Configure Model Context Protocol (MCP) server endpoints, database backends, and authentication tokens to securely authorize client applications to interact with your developer portal.

This configuration is a prerequisite for MCP clients to use the defined MCP tools and access the exposed capabilities of {product-very-short}.

.Prerequisites

* You have {model-context-protocol-book-link}#install-the-mcp-server-and-tool-plugins-in-red-hat-developer-hub[installed the MCP server and tool plugins in {product}].

.Procedure

. In your {product} `{my-app-config-file}` file, configure a static token for authentication against the MCP server endpoint. MCP clients (such as `Cursor`, `Continue`, or `Lightspeed Core`) use these tokens to authenticate against the {backstage} MCP server. For example:
+
[source,yaml]
----
backend:  
  auth:
    externalAccess:
      - type: static
        options:
          token: ${MCP_TOKEN}
          subject: mcp-clients
----
where:

`${MCP_TOKEN}`:: Set the token value that you generate manually and share with your MCP clients.
+
[NOTE]
====
Tokens must be long and complex strings without whitespace to prevent brute-force guessing.

. To generate a sample token, use the following command:
[source,bash]
----
$ node -p `require("crypto").randomBytes(24).toString("base64")`
----
====

. Register the MCP tools that you install as a plugin source in your `{my-app-config-file}` file:

** To use the installed `extras` plugins, you must register them as plugin sources:
+
[source,yaml,subs="+attributes,+quotes"]
----
backend:
  actions:
    pluginSources:
      - software-catalog-mcp-extras
      - techdocs-mcp-extras
      - scaffolder-mcp-extras
----

** To fetch entities or manage components, you must register the catalog plugin source. If your workflow requires scaffolding tools, you must also register the scaffolder plugin source. These plugins are optional and required only when using these specific tools.
+
[source,yaml,subs="+attributes,+quotes"]
----
backend:
  actions:
    pluginSources:
      - catalog
      - scaffolder
----

** As a least-privilege best practice, enable only the plugin sources required for your use case. For example, if scaffolder tools are not needed:
+
[source,yaml,subs="+attributes,+quotes"]
----
backend:
  actions:
    pluginSources:
      - software-catalog
      - techdocs-mcp-extras
      # - scaffolder  # uncomment if scaffolder tools are needed
----

** If you are using OpenAI models with the {product-very-short} MCP server, add the following configuration to your `{my-app-config-file}` file to disable namespaced toolnames:
+
[source,yaml,subs="+attributes,+quotes"]
----
mcpActions:
  namespacedToolNames: false
----

+
[source,yaml,subs="+attributes,+quotes"]
----
# Full `{my-app-config-file}` file example with MCP configuration
app:
  title: AI Dev {product-short}
  baseUrl: "${{product-very-short}_BASE_URL}"
auth:
  environment: development
  session:
    secret: "${BACKEND_SECRET}"
  providers:
    guest:
      dangerouslyAllowOutsideDevelopment: true
backend:
  actions:
    pluginSources:
      - software-catalog-mcp-extras
      - techdocs-mcp-extras
      - scaffolder-mcp-extras
      - catalog
      - scaffolder
  auth:
    externalAccess:
      - type: static
        options:
          token: ${MCP_TOKEN}
          subject: mcp-clients
    keys:
      - secret: "${BACKEND_SECRET}"
  baseUrl: "${{product-very-short}_BASE_URL}"
  cors:
    origin: "${{product-very-short}_BASE_URL}"
signInPage: oidc
----

. Apply an action filter to limit which MCP tools are exposed to AI clients. Red Hat recommends exposing only read-only tools by default to minimize risk:
+
[source,yaml]
----
backend:
  actions:
    filter:
      include:
        - attributes:
            readOnly: true
----
+
If your use case requires write-enabled or potentially destructive tools, you must explicitly configure them:
+
[source,yaml]
----
backend:
  actions:
    filter:
      include:
        - attributes:
            readOnly: false
            destructive: true
----
+
The following table lists the tools that are not read-only and their risk level:
+
[cols="30%,35%,17%,18%",options="header"]
|===
|Tool |Plugin source |readOnly |destructive
|`scaffolder-execute-template` |`scaffolder-mcp-extras` |`false` |`true`
|`catalog-register-tool` |`software-catalog-mcp-extras` |`false` |`false`
|`catalog-unregister-tool` |`software-catalog-mcp-extras` |`false` |`true`
|`scaffolder-execute-template` (upstream) |`scaffolder` |`false` |`true`
|===
