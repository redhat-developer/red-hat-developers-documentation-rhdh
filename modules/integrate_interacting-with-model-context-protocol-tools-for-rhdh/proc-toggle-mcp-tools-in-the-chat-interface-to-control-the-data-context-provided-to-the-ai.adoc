= Toggle MCP tools in the chat interface

[role="_abstract"]
Use the {ls-brand-name} chat interface options to securely configure your personal tokens, toggle specific Model Context Protocol (MCP) services, and directly control the data context made available to the AI assistant.

You can use the *MCP servers* panel in the {ls-short} chat interface to review server status and enable or disable specific MCP servers for your session. Individual tool names are visible in the server settings modal for each server, not in the main server list.

.Prerequisites

* An administrator has configured encryption and database storage for the backend.
* For servers that require authentication, you have a valid token or organization credential. Some servers, such as Dynamic Client Registration (DCR) servers, do not require a manual token.

.Procedure

. In the {ls-brand-name} chat box, click the *Chatbot options* menu icon in the header.
. Select *MCP settings*.

. In the *MCP servers* panel, review the list of available servers. Each server displays its name, status, and an on/off toggle.
+
image::integrate_interacting-with-model-context-protocol-tools-for-rhdh/lightspeed-chat-edit-mcp.png["MCP servers panel showing server names, statuses, toggles, and the Edit icon"]
+
The following statuses are possible:
+
** *X tool* / *X tools*: The server is connected and has the specified number of tools available.
** *Token required*: The server requires authentication before it can be enabled.
** *Disabled*: The server is currently turned off.
** *Failed*: The server connection has failed.
** *Unknown*: The server status could not be determined.

. To configure a server, click the *Edit* icon next to the server. In the server settings modal, you can perform the following actions:
+
image::integrate_interacting-with-model-context-protocol-tools-for-rhdh/lightspeed-chat-mcp-settings.png["MCP server settings modal showing status, available tools, and authentication options"]

** Review the info bar, which confirms that credentials are encrypted and operations use your exact permissions.
** Review the *Status* of the server. For a connected server, the modal also lists the individual tools that the server provides.
** *Enable or disable the server*: Use the *Enabled* toggle to turn the server on or off. If the token is valid, the server is enabled automatically.
+
[NOTE]
====
You must configure a token before you can enable a server that requires authentication.
====
** *Configure authentication*: The available authentication options depend on how the server is configured:
*** For a server that requires a personal token, enter your Personal Access Token in the *Authentication token* field and click *Save*. The system validates the token automatically.
+
image::integrate_interacting-with-model-context-protocol-tools-for-rhdh/lightspeed-chat-mcp-missing-default-token.png["MCP server settings modal with a personal Authentication token field"]
*** For a server that provides an organization default token, select *Use organization default token* to use the token that your administrator configured, or select *Use personal token* to enter your own token. If you select *Use personal token*, enter it in the *Authentication token* field and click *Save*.
+
image::integrate_interacting-with-model-context-protocol-tools-for-rhdh/lightspeed-chat-mcp-server-authentication.png["MCP server settings modal with organization default token and personal token options"]
*** For a Dynamic Client Registration (DCR) server, no manual token is required. The modal displays an information alert explaining that tokens are minted automatically from your user identity.
+
image::integrate_interacting-with-model-context-protocol-tools-for-rhdh/lightspeed-chat-mcp-server-with-dcr-auth.png["MCP server settings modal for a server that uses DCR authentication"]
** *Remove a token*: Click *Remove personal token* to remove your stored token. An alert message confirms: "Token has been removed. To use this MCP server again, provide a new token."

.Verification

. Submit a query in the chat that requires an MCP tool, such as requesting catalog resources or server information.
. If you enabled a server, verify that the response contains data from that specific MCP tool.
. If you disabled a server, verify that {ls-short} uses standard documentation or general knowledge instead of the MCP tool to provide the response.
