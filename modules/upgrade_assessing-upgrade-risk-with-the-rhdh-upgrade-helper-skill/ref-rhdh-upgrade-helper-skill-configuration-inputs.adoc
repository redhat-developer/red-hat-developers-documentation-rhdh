= Configuration inputs for the {product-very-short} Upgrade Helper skill

[role="_abstract"]
The {product-very-short} Upgrade Helper skill requires specific configuration files to analyze your {product} deployment. The following tables describe the required and optional inputs, and the available command-line flags.

== Required inputs

[cols="1,2,2",options="header"]
|===
|Input |Flag |Description

|Application configuration
|`--config <path>`
|Path to your `app-config.yaml` file. This file contains the {product} application runtime configuration. You can specify this flag more than once to include additional configuration files, such as environment-specific overlays.

|Dynamic plugins configuration
|`--plugins <path>`
|Path to your dynamic plugins configuration YAML file. This file controls which plugins are enabled, their versions, and any overrides applied to your deployment.
|===

== Optional inputs

[cols="1,2,2",options="header"]
|===
|Input |Flag |Description

|Environment variables
|`--env <path>`
|Path to a file containing runtime environment variable values (for example, a `.env` file). Include only variables that affect {product-very-short} behaviour. Do not include secrets.

|Additional configuration files
|`--config <path>` (repeated)
|Path to any additional configuration files relevant to your deployment, such as production overlays or custom backend configuration files.
|===

== Version flags

[cols="1,2",options="header"]
|===
|Flag |Description

|`--from <version>`
|The {product-very-short} version currently installed in your environment. For example, `1.8`.

|`--to <version>`
|The {product-very-short} version you intend to upgrade to. For example, `1.10` or `2.1`.
|===

When you use `--from` and `--to` to specify a range that skips multiple minor versions, the skill produces a cumulative report covering all breaking changes, configuration changes, and plugin compatibility issues across every skipped release.

== Secrets handling

The skill checks all provided input files for content that appears to contain secret values, such as API keys, tokens, or passwords, before processing them. If the skill flags a file, remove or replace the secret values with placeholders and re-run the skill.

[IMPORTANT]
====
Do not provide configuration files or environment variable exports that contain live secret values. The skill warns against including secrets, but you are responsible for ensuring that sensitive data is not present in any files you provide.
====
