= Approve the Operator InstallPlan

[role="_abstract"]
To complete the upgrade when the {product} Operator subscription uses manual approval, approve the pending `InstallPlan` from the {ocp-short} web console.

.Prerequisites

* You have logged in as an administrator on the {ocp-short} web console.
* An upgrade is available for the {product} Operator.

.Procedure

. In the *Administrator* perspective of the {ocp-short} web console, click *Operators > Installed Operators*.
. On the *Installed Operators* page, click *{product} Operator*.
. On the *{product} Operator* page, click the *Subscription* tab.
. From the *Upgrade status* field on the *Subscription details* page, click *Upgrade available*. If there is no upgrade available, the *Upgrade status* field value is *Up to date*.
+
[WARNING]
====
If you are upgrading from 1.10 to 2.1 and you use the Operator-managed local PostgreSQL database, approving this `InstallPlan` changes the default PostgreSQL image from version 15 to version 18. An existing PostgreSQL 15 data directory does not start on PostgreSQL 18, so the database enters a crash loop and {product} becomes unavailable.

Before you approve the `InstallPlan`, migrate the database by following xref:proc-upgrade-local-postgresql-15-to-18-operator_migrate-from-rhdh-1-10-to-2-1[Upgrade the local PostgreSQL database for Operator deployments], which approves the `InstallPlan` at the correct point in the migration. To keep PostgreSQL 15 instead, that procedure explains how to override `RELATED_IMAGE_postgresql` with the full 1.10 image reference, including its digest, in the Operator Subscription before you approve.
====
. On the *`InstallPlan` details* page, click *Preview `InstallPlan` > Approve*.

.Verification

* The *Upgrade status* field value on the *Subscription details* page is *Up to date*.
