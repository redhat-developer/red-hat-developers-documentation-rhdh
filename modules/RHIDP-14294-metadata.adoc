= Network policy values

[role="_abstract"]

Use network policy values to customize your {product-very-short} backend and database network policies in the in `networkpolicy.yaml` file.

Backend policies::
[cols="1,1"]
|===
d|*Key* |*Description*

|`spec.podSelector.matchLabels[rhdh.redhat.com/app] = backstage-<cr-name>`
|Backend policies
|===

Database policies::
[cols="1,1,1"]
|===
d|*Key* |*Port* |*Description*

|`spec.podSelector.matchLabels[rhdh.redhat.com/app] = backstage-psql-<cr-name>`
|-
|Database policies. Local database must be enabled.

The placeholder value in `podSelector.matchLabels` (`backstage` or `backstage-psql`) determines if a policy targets the backend or the database at runtime.

|`allow-psql-egress`
|5432 TCP
|If you use external databases and local database is disabled, the policy allows egress on this specific port to any destination.

|`allow-redis-egress`
|6379 TCP
|If you use Redis databases, the policy allows egress on this specific port to any destination.

If you use {product-very-short} with Operator, you must use your own instance of Redis. The database is not deployed by the Operator.

|`allow-https-egress`
|6443 TCP or 443 UDP
|If you use plugins that query cluster resources, the policy allows egress on port 6443 TCP (Kubernetes API server).

On some managed platforms, such as GKE and EKS, the API server listens on port 443 instead.

|`allow-metrics-ingress`
|9464 UDP
| The policy allows ingress on this specific port from `openshift-monitoring`, `openshift-user-workload-monitoring`, GKE GMP namespaces (`gmp-system`, `gke-gmp-system`), and `monitoring` (kube-prometheus-stack convention).
