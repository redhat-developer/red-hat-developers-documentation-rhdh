= Understanding the OGX entity provider

include::{docdir}/artifacts/snip-developer-preview-rhoai.adoc[]

[role="_abstract"]
The OGX entity provider ingests AI models and AI agents into the {product} ({product-very-short}) Catalog so that developer teams can discover and consume them alongside other catalog entities.

The OGX entity provider reads from the OGX Model Server, formerly known as LlamaStack, that is provided by {rhoai-brand-name} ({rhoai-short}) 3.5 and later. Because the OGX Model Server is another subcomponent of {rhoai-short}, the OGX entity provider broadens the scope of the {openshift-ai-connector-name}, which already connects {product-very-short} to {rhoai-short} capabilities such as the model catalog and model-serving (KServe) plugins. It performs two tasks:

Ingests AI models::
The provider queries the OGX Model Server for the models that it serves and represents them in the catalog as `AiModelServerAPI` entities. The `AiModelServerAPI` entity kind was introduced in {product-very-short} {product-version} to represent AI model servers and the models that they serve. This is the same entity kind that the {openshift-ai-connector-name} uses to represent {rhoai-short} model servers through its model catalog and model-serving (KServe) plugins. For more information, see the {openshift-ai-connector-for-rhdh-book-link}[{openshift-ai-connector-for-rhdh-book-title}] guide.

Imports AI agents::
Since OGX does not provide an endpoint for discovering agents, as a potential convenience, the provider reads the OpenAI Agent SDK compatible agents that you define in its configuration and imports them into the catalog as `AiResource` entities with `spec.type: agent`. The `agent` value of `spec.type` extends the existing upstream `AiResource` entity kind, which represents AI skills and rules.
+
You can also define `AiResource` entities with `spec.type: agent` in traditional `catalog-info.yaml` files that you register into the catalog through the {product-very-short} console. These entities use the same schema that the provider imports. The AI Asset entity model reference provides an example `AiResource` agent entity and the annotations that it requires.

The AI Asset entity model reference provides the full mapping of AI asset categories to entity kinds, and the annotations that classify each entity.
